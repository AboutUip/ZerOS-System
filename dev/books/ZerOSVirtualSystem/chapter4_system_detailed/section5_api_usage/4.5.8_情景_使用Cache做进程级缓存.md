# 4.5.8 情景：使用 Cache.* 做进程级缓存

## 情景描述

有些数据**计算或拉取成本较高**，但在一段时间内又会被同一个程序多次使用，例如：  
- 设置页面读取的“系统配置快照”；  
- 某个网络请求的结果；  
- 复杂计算的中间结果。  

这类数据适合放到 ZerOS 的 **CacheDrive** 对应的 `Cache.*` API 中。  
`kernelAPIs` 中的 `Cache.set / Cache.get / Cache.has / Cache.delete / Cache.clear / Cache.getStats` 会自动在 `options` 里补上调用者的 `pid`，从而实现**按进程区分的缓存空间**。

---

## 前置条件

- 应用持有 `this.pid`。  
- CacheDrive 已初始化（系统默认在内核层完成）。  
- 具备访问缓存所需的权限（如果有单独的缓存权限位，以实际实现为准）。  

---

## 情景 A：为网络请求结果做本地缓存

```js
// 在某个前端应用中
const CACHE_KEY_USER_PROFILE = 'app_user_profile';

async function fetchUserProfileFromServer() {
    // 真实的网络请求逻辑（略）
    const response = await fetch('/api/profile');
    if (!response.ok) throw new Error('请求用户信息失败');
    return await response.json();
}

async function getUserProfile() {
    // 1. 先从 Cache 中尝试读取
    const cached = await ProcessManager.callKernelAPI(this.pid, 'Cache.get', [
        CACHE_KEY_USER_PROFILE,
        null,             // defaultValue
        { ttl: 60 }       // options：例如允许 CacheDrive 使用 ttl 信息（具体字段由驱动决定）
    ]);

    if (cached !== null && cached !== undefined) {
        return cached;
    }

    // 2. 未命中缓存，则从服务器拉取
    const profile = await fetchUserProfileFromServer();

    // 3. 写入缓存（与当前 pid 自动关联）
    await ProcessManager.callKernelAPI(this.pid, 'Cache.set', [
        CACHE_KEY_USER_PROFILE,
        profile,
        { ttl: 60 }   // 例如缓存 60 秒，具体含义由 CacheDrive 决定
    ]);

    return profile;
}
```

要点：  
- `Cache.get` 的参数是 `[key, defaultValue, options]`；`options` 中如果没有 `pid`，内核会自动补上当前调用者的 pid。  
- `Cache.set` 的参数是 `[key, value, options]`，同样自动补 `pid`。

## 情景 B：检查、删除和清空当前进程缓存

```js
async function clearProfileCache() {
    const key = CACHE_KEY_USER_PROFILE;

    // 先判断是否存在
    const exists = await ProcessManager.callKernelAPI(this.pid, 'Cache.has', [
        key,
        {}   // options，可留空对象，pid 会由内核补上
    ]);
    if (!exists) return;

    // 删除单个 key
    await ProcessManager.callKernelAPI(this.pid, 'Cache.delete', [
        key,
        {}
    ]);
}

async function clearAllMyCache() {
    // 仅清除“当前进程”相关的缓存
    await ProcessManager.callKernelAPI(this.pid, 'Cache.clear', [
        {}   // options，可附带自定义策略，以 CacheDrive 实现为准
    ]);
}
```

## 情景 C：在调试工具中查看缓存统计信息

```js
async function showCacheStats() {
    const stats = await ProcessManager.callKernelAPI(this.pid, 'Cache.getStats', [
        {}   // options，同样会自动带上 pid
    ]);

    console.log('当前进程缓存统计:', stats);
    // 统计结构由 CacheDrive.getStats 决定，通常包含条目数量、占用大小等
}
```

---

## 行为小结

| API | 典型 args | 用途 |
|-----|-----------|------|
| `Cache.set` | `[key, value, options]` | 为当前进程写入一条缓存记录（支持 ttl 等附加选项） |
| `Cache.get` | `[key, defaultValue, options]` | 读取缓存；未命中时返回默认值 |
| `Cache.has` | `[key, options]` | 判断 key 是否存在 |
| `Cache.delete` | `[key, options]` | 删除某个 key 对应的缓存 |
| `Cache.clear` | `[options]` | 清除当前进程相关的缓存（具体范围由实现决定） |
| `Cache.getStats` | `[options]` | 获取缓存统计信息（条目数、大小等） |

通过这些情景，你可以把 `Cache.*` 看作“比 LocalStorage 更灵活、按进程区分的内存+磁盘混合缓存层”，适合做**性能优化和热点数据本地化**。
