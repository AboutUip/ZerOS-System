# 4.5.5 情景：任务栏图标与前后台切换

## 情景描述

典型桌面系统中，应用都会在**任务栏**留下图标，用户可以点击图标在前后台之间切换窗口。ZerOS 中，这一行为由系统层的 `TaskbarManager` / `GUIManager` 等模块协作完成，其中：

- 通过 `Taskbar.*` API（`Taskbar.addIcon / Taskbar.updateIcon / Taskbar.removeIcon` 等）管理**自定义图标**；
- 通过 GUI 层（第 4 章前文讲解的 `GUIManager`）管理窗口的显示/隐藏/前后台。

本节从应用视角，说明一个程序如何：在启动时**创建一个与自身 PID 绑定的任务栏图标**，以及在退出前**移除该图标**。窗口前后台切换的具体行为依赖 GUI 层实现，这里只在行为上做简要描述。

---

## 情景 A：程序启动时创建自定义任务栏图标

```js
// 程序入口（如 App/main.js）
async function init() {
    // 1. 创建一个与当前进程绑定的自定义任务栏图标
    const result = await ProcessManager.callKernelAPI(this.pid, 'Taskbar.addIcon', [{
        title: '我的应用',
        icon: 'D:/icons/my-app.png',   // 图标路径或资源 ID
        tooltip: '点击切换到我的应用'
        // 其它字段由 TaskbarManager.addCustomIcon 实现定义
    }, this.pid]);

    // 建议保存返回的 iconId，便于后续更新/删除
    this._taskbarIconId = result && result.iconId;

    // 2. 打开主窗口（窗口管理的细节见 GUIManager 相关小节，本处不通过 kernel API 展开）
    openMainWindow();  // 例如调用系统层提供的窗口打开函数
}
```

要点：

- `Taskbar.addIcon` 的参数是 `[options, pid]`：  
  - `options` 为图标配置对象；  
  - `pid` 用于在内核侧自动关联“哪个进程创建了该图标”，从而在移除/更新时做权限校验。  
- 内部实际调用的是 `TaskbarManager.addCustomIcon`，具体可在系统层源码中查看。

---

## 情景 B：更新与移除任务栏图标

在程序运行过程中，可能需要根据状态改变图标（例如有未读消息时显示小红点），以及在退出前移除图标：

```js
async function updateTaskbarIconStatus(hasUnread) {
    if (!this._taskbarIconId) return;

    await ProcessManager.callKernelAPI(this.pid, 'Taskbar.updateIcon', [
        this._taskbarIconId,
        {
            badge: hasUnread ? '●' : '',
            tooltip: hasUnread ? '有未读消息' : '我的应用'
        },
        this.pid
    ]);
}

async function cleanupTaskbarIcon() {
    if (!this._taskbarIconId) return;

    await ProcessManager.callKernelAPI(this.pid, 'Taskbar.removeIcon', [
        this._taskbarIconId,
        this.pid
    ]);
}
```

要点：

- `Taskbar.updateIcon` 的参数是 `[iconId, updates, pid]`；  
  - 内核会检查该 `iconId` 是否由 `pid` 对应的进程创建，防止跨进程篡改图标。  
- `Taskbar.removeIcon` 的参数是 `[iconId, pid]`，同样只允许删除自己创建的图标。

前后台切换、窗口最小化/恢复的行为主要由 `GUIManager` 与任务栏内部逻辑控制：  
应用的关键职责是**创建/更新/删除“属于自己”的任务栏图标**，以反映自己的运行状态。

---

## 行为小结

| 步骤 | 行为 |
|------|------|
| 创建任务栏图标 | 程序启动时调用 `Taskbar.addIcon`，传入图标配置和 `pid`，系统层在任务栏中渲染图标 |
| 更新任务栏图标 | 运行过程中调用 `Taskbar.updateIcon`，根据业务状态（如未读消息）更新图标显示 |
| 移除任务栏图标 | 程序退出前调用 `Taskbar.removeIcon`，只删除自己创建的图标 |

通过这个情景，你可以把“任务栏图标”理解为：应用通过 `Taskbar.*` 系列 API 在系统任务栏中声明和维护自己的存在，而具体的“点击后如何切到前台窗口”逻辑由 `TaskbarManager` 与 `GUIManager` 在系统层内部协作完成（详见第 4 章前文的系统层实现）。
