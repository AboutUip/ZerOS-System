# 4.5.4 情景：事件订阅与跨窗口通信

## 情景描述

你有两个前端程序：一个是“下载管理器”窗口，另一个是“通知中心”或“任务栏”。当下载完成时，希望下载管理器**发出事件**，由通知中心或任务栏**自动更新状态/弹出提示**。这类需求适合使用 ZerOS 的**事件系统**。

本节从应用视角示例如何通过 `ProcessManager.callKernelAPI` 调用 `Event.register` / `Event.emit`，完成简单的“跨窗口通信”。

---

## 前置条件

- 两个程序各自有自己的 `pid`（如 `this.pid`）。
- 系统层已加载 `EventManager`，并对外提供 `Event.register` / `Event.emit` 相关内核 API（具体命名以实际实现为准，下文使用常见命名进行说明）。

---

## 情景 A：通知中心订阅“下载完成”事件

假设我们约定事件名为 `'download:finished'`，通知中心在启动时订阅该事件：

```js
// 通知中心程序（NotificationCenter/main.js）
async function init() {
    // handler 由系统层 / GUI 层负责绑定，这里假设通过 callKernelAPI 注册逻辑事件
    await ProcessManager.callKernelAPI(this.pid, 'Event.register', [
        'download:finished',
        async (payload) => {
            // payload 结构自定义，例如 { id, name, size }
            await ProcessManager.callKernelAPI(this.pid, 'Notification.create', [{
                title: '下载完成',
                message: `${payload.name} 已下载完成`
            }]);
        },
        { once: false } // 可选：是否只触发一次等
    ]);
}
```

要点：

- 第一个参数是事件名，如 `'download:finished'`。
- 第二个参数是回调函数，由系统层包装后与 pid 绑定。
- 第三个参数是可选配置，例如是否一次性事件等。

---

## 情景 B：下载管理器在任务完成时发出事件

```js
// 下载管理器程序（Downloader/main.js）
async function onDownloadFinished(fileInfo) {
    // fileInfo 例如 { id, name, size }
    await ProcessManager.callKernelAPI(this.pid, 'Event.emit', [
        'download:finished',
        fileInfo
    ]);
}
```

当下载完成时调用 `onDownloadFinished`，事件系统将通知所有订阅 `download:finished` 的处理函数（包括通知中心）。

---

## 行为小结

| 角色 | 行为 |
|------|------|
| 通知中心 | 使用 `Event.register` 订阅 `download:finished`，回调里通过 `Notification.create` 弹出系统通知 |
| 下载管理器 | 在任务完成时调用 `Event.emit('download:finished', payload)` |
| 内核 / 系统层 | 负责维护事件订阅表、按进程和事件名分发回调，并在进程退出时自动清理 |

通过这种方式，你可以把“跨窗口通信”抽象成**事件流**，应用只需要关心“发什么事件、带什么数据、谁去订阅”，其余由事件系统负责。
