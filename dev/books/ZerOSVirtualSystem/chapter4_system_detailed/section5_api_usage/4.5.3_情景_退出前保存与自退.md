# 4.5.3 情景：程序退出前保存与自退

## 情景描述

应用在用户点击“退出”或窗口关闭时，需要：**先保存当前状态（如草稿、配置）到本地，再请求内核结束本进程**。这涉及两个内核 API 的配合使用：

1. `LocalStorage.set` 或 `FileSystem.write`：把数据持久化（参见 4.5.2）。
2. `Process.requestSelfTermination`：向内核申请“结束当前进程”，由 `ProcessManager` 做资源回收与清理。

本节只强调**调用顺序**和**核心代码**，不重复读写 API 的细节。

---

## 前置条件

- 应用持有 `this.pid`。
- 已具备 `KERNEL_LSTORAGE`（若用 LocalStorage）或 `KERNEL_DISK_WRITE`（若用 FileSystem），以及 `Process.requestSelfTermination` 所需权限（若有单独权限项）。

---

## 核心代码

### 1. 先保存再自退（推荐顺序）

```js
async function exitAndSave() {
    // 1. 先持久化：避免进程被回收后未保存的数据丢失
    try {
        await ProcessManager.callKernelAPI(this.pid, 'LocalStorage.set', ['app_draft', getCurrentDraft()]);
    } catch (e) {
        console.warn('保存草稿失败:', e.message);
    }

    // 2. 再请求自退；内核会做进程表清理、资源释放等
    await ProcessManager.callKernelAPI(this.pid, 'Process.requestSelfTermination', []);
}
```

要点：

- **先写存储、再调 `requestSelfTermination`**。若顺序反了，自退后进程可能已被回收，再 `callKernelAPI` 可能失败或行为未定义。
- `Process.requestSelfTermination` 的 `args` 一般为 `[]`（无额外参数），表示“当前 pid 对应的进程请求退出”。

### 2. 仅请求自退（无保存）

```js
async function requestExit() {
    await ProcessManager.callKernelAPI(this.pid, 'Process.requestSelfTermination', []);
}
```

### 3. 错误处理

自退请求一般不应被应用层“吞掉”，以便用户或日志知道是否成功；保存失败则可根据业务决定是否仍执行退出：

```js
async function exitAndSave() {
    let saveOk = false;
    try {
        await ProcessManager.callKernelAPI(this.pid, 'LocalStorage.set', ['app_draft', getCurrentDraft()]);
        saveOk = true;
    } catch (e) {
        console.warn('保存失败:', e.message);
    }

    try {
        await ProcessManager.callKernelAPI(this.pid, 'Process.requestSelfTermination', []);
    } catch (e) {
        console.error('退出请求失败:', e.message);
    }
}
```

---

## 行为小结

| 步骤 | 行为 |
|------|------|
| 1. `LocalStorage.set` / `FileSystem.write` | 将当前需要保留的数据写入内核管理的存储 |
| 2. `Process.requestSelfTermination` | 内核回收该 pid 对应进程、释放资源；此后该 pid 不再有效 |

这样，你就完成了“退出前保存 + 自退”的完整情景；其它需要“先做 A 再做 B”的流程，同样注意 `callKernelAPI` 的顺序即可。
