# 4.5.7 情景：端口注册与发送数据

## 情景描述

有些 ZerOS 程序需要在本机打开一个“服务端口”，供其他程序或外部工具连接；还有一些命令行工具（例如 `netport`），需要向某个端口发送数据做调试或控制。  

内核通过 `Network.Port.*` 提供端口管理能力：  
- `Network.Port.register` / `Network.Port.unregister` / `Network.Port.list` / `Network.Port.getStatus`  
- `Network.Port.send`  

本节用两个情景说明：**应用注册端口作为服务端**，以及**命令行工具发送数据到该端口**。

---

## 前置条件

- 调用这些 API 的程序通常需要较高权限（例如管理员 + `NETWORK_ACCESS`），以避免随便开监听端口。  
- 调用方式依旧是 `ProcessManager.callKernelAPI(this.pid, apiName, args)`。  

---

## 情景 A：应用启动时注册服务端口

假设你写了一个“本地小服务”，希望监听 `127.0.0.1:8080`，供其它程序或外部脚本连接：

```js
// 服务应用（例如 LocalServer/main.js）
async function initServer() {
    const port = 8080;
    const programName = 'LocalServer';

    try {
        const result = await ProcessManager.callKernelAPI(this.pid, 'Network.Port.register', [
            port,
            this.pid,
            programName,
            {
                // options 对象由 ProcessManager.registerPort 定义
                // 可以包含如 address、maxConnections、protocol 等信息（以实际实现为准）
            }
        ]);

        // 约定：result.success 表示注册是否成功（参见内核实现）
        if (result && result.success) {
            console.log(`端口 ${port} 注册成功，程序名: ${programName}, PID: ${this.pid}`);
        } else {
            console.warn(`端口 ${port} 注册失败: ${result?.message || '未知错误'}`);
        }
    } catch (e) {
        console.error(`端口 ${port} 注册失败:`, e.message);
    }
}
```

要点：  
- `Network.Port.register` 的 `args` 是 `[port, pid, programName, options]`。  
- 内核会严格检查 `port` 和 `pid` 是否为数字，否则抛出“无效的端口号/进程ID”错误。  

应用在退出前，最好**显式取消注册**：

```js
async function cleanupServer() {
    const port = 8080;
    try {
        const result = await ProcessManager.callKernelAPI(this.pid, 'Network.Port.unregister', [port]);
        if (result && result.success) {
            console.log(`端口 ${port} 已取消注册`);
        }
    } catch (e) {
        console.warn(`取消端口 ${port} 注册失败:`, e.message);
    }
}
```

## 情景 B：使用 CLI 工具查看端口状态与列表

命令行工具 `netport` 就是基于这些 API 实现的。  
如果你想在应用里做一个更图形化的“端口管理器”，可以类似这样调用：

```js
// 端口管理器应用
async function refreshPortList() {
    const ports = await ProcessManager.callKernelAPI(this.pid, 'Network.Port.list', []);
    // ports 的具体结构由 ProcessManager.listPorts 决定，一般包含 port / pid / programName / status / address 等字段
    renderPortTable(ports);
}

async function showPortStatus(port) {
    const status = await ProcessManager.callKernelAPI(this.pid, 'Network.Port.getStatus', [port]);
    // status 结构参考 netport.js 中的使用：status.status, status.programName, status.pid, status.address, status.connections 等
    renderPortStatus(status);
}
```

要点：  
- `Network.Port.list` 的 `args` 是 `[]`。  
- `Network.Port.getStatus` 的 `args` 是 `[port]`，并会在内核内部把字符串端口转换为数字并校验范围。

## 情景 C：向某个端口发送数据

```js
// 发送调试数据到本机 8080 端口
async function sendDebugData() {
    const host = '127.0.0.1';
    const port = 8080;
    const data = 'Hello ZerOS';

    try {
        const result = await ProcessManager.callKernelAPI(this.pid, 'Network.Port.send', [
            host,
            port,
            data
        ]);

        // 约定：result.bytesWritten 可能存在，表示发送的字节数（参见 netport.js 的使用）
        if (result && typeof result.bytesWritten !== 'undefined') {
            console.log(`已向 ${host}:${port} 发送数据，字节数: ${result.bytesWritten}`);
        } else {
            console.log(`已向 ${host}:${port} 发送数据`);
        }
    } catch (e) {
        console.error(`发送数据到 ${host}:${port} 失败:`, e.message);
    }
}
```

要点：  
- `Network.Port.send` 的 `args` 是 `[host, port, data]`。  
- 内核会校验 `port` 是否为合法整数，非法时直接抛错。  

---

## 行为小结

| API | 典型 args | 用途 |
|-----|-----------|------|
| `Network.Port.register` | `[port, pid, programName, options]` | 注册端口监听，建立端口到进程/程序名的映射 |
| `Network.Port.unregister` | `[port]` | 取消端口监听 |
| `Network.Port.getStatus` | `[port]` | 查询指定端口当前状态（绑定进程、连接列表等） |
| `Network.Port.list` | `[]` | 列出所有已注册端口 |
| `Network.Port.send` | `[host, port, data]` | 向指定主机/端口发送数据 |

通过这些情景，你可以把 `Network.Port.*` 系列 API 理解为 ZerOS 的“本地端口管理与数据发送接口”，适合服务型应用与诊断工具复用。
