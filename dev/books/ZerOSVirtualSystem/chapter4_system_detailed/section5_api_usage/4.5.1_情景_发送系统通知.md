# 4.5.1 情景：发送系统通知

## 情景描述

你的应用在**任务完成**或**需要提醒用户**时，希望弹出**系统级通知**（标题 + 内容、可选自动消失）。例如：下载完成、定时提醒、或“欢迎使用”的启动提示。内核通过 `Notification.create` 和 `Notification.remove` 提供该能力，应用必须通过 `ProcessManager.callKernelAPI` 调用，并具备 `SYSTEM_NOTIFICATION` 权限。

---

## 前置条件

- 应用已启动，并持有 `this.pid`（由 `ProcessManager` 在启动时注入）。
- 应用已申请或被授予 **系统通知** 权限（`PermissionManager.PERMISSION.SYSTEM_NOTIFICATION`）；若未授权，首次调用时可能会触发权限请求 UI。

---

## 核心代码

### 1. 发送一条通知（并拿到通知 ID）

```js
// 在应用脚本中（如 main.js），假设 this.pid 已存在
async function showWelcomeNotification() {
    const result = await ProcessManager.callKernelAPI(this.pid, 'Notification.create', [{
        title: '欢迎使用',
        message: '应用已就绪，您可以开始使用了。',
        type: 'snapshot',   // 可选：snapshot | 其他类型，与 NotificationManager 约定一致
        duration: 3000      // 可选：毫秒，0 表示不自动关闭
    }]);

    // 返回格式：{ status: 'success', data: { id: notificationId } }
    const notificationId = result?.data?.id;
    if (notificationId) {
        console.log('通知已显示，ID:', notificationId);
        // 若需要稍后关闭，可保存 notificationId 再调 Notification.remove
    }
}
```

要点：

- **第一个参数**一定是 `this.pid`，否则会触发调用栈与 PID 校验失败。
- **第二个参数**是 API 名：`'Notification.create'`。
- **第三个参数**是**参数数组**；这里 `create` 只收一个对象，所以是 `[options]`。options 里常用：`title`、`message`（或 `content`）、`type`、`duration`。

### 2. 主动关闭某条通知

若你保存了创建时返回的 `id`，可以在合适时机（如用户点击“知道了”或定时）移除通知：

```js
async function closeNotification(notificationId) {
    await ProcessManager.callKernelAPI(this.pid, 'Notification.remove', [notificationId]);
    // 无异常即表示移除成功
}
```

这里 `args` 是 `[notificationId]`，且 `notificationId` 必须是**字符串**（与内核 `Notification.remove` 约定一致）。

### 3. 错误处理（权限被拒或参数错误）

```js
async function showNotificationSafely(title, message) {
    try {
        const result = await ProcessManager.callKernelAPI(this.pid, 'Notification.create', [{
            title,
            message
        }]);
        return result?.data?.id ?? null;
    } catch (e) {
        // 常见：权限未授予、pid 校验失败、或 NotificationManager 未加载
        console.warn('通知发送失败:', e.message);
        return null;
    }
}
```

---

## 行为小结

| 步骤 | 行为 |
|------|------|
| `callKernelAPI(this.pid, 'Notification.create', [options])` | 内核校验 pid、调用栈、权限（`SYSTEM_NOTIFICATION`），通过后执行 `Notification.create` handler |
| handler 内部 | 将 `options` 转为 `NotificationManager` 所需格式，调用 `NotificationManager.createNotification(pid, notificationOptions)`，返回 `notificationId` |
| 应用拿到 `result.data.id` | 可用于后续 `Notification.remove` 关闭该条通知 |

这样，你就完成了一次“情景 → 如何传参 → 如何拿返回值 → 如何删通知”的完整使用流程；其他 API 的用法也遵循同样的 `callKernelAPI(pid, apiName, args)` 模式。
