# 4.5.6 情景：网络开关与状态查询

## 情景描述

有些应用需要根据**系统网络状态**做不同处理：  
- 启动时检查是否联网，决定要不要自动更新；  
- 用户在设置里手动“打开/关闭网络”；  
- 状态栏或诊断工具要显示当前网络信息。  

内核通过 `Network.*` 提供这一能力：`Network.getInfo`、`Network.getState`、`Network.isOnline`、`Network.getConnectionInfo`、`Network.enable`、`Network.disable`、`Network.toggle`，应用通过 `ProcessManager.callKernelAPI` 调用。

---

## 前置条件

- 应用持有 `this.pid`。  
- 已具备网络相关权限（例如 `PermissionManager.PERMISSION.NETWORK_ACCESS`，具体以系统权限枚举为准）。  

---

## 情景 A：启动时检查网络并决定是否弹出提示

```js
// 设置应用或启动器中的初始化逻辑
async function initApp() {
    // 1. 查询基本网络信息
    const info = await ProcessManager.callKernelAPI(this.pid, 'Network.getInfo', []);
    // 2. 判断当前是否在线
    const isOnline = await ProcessManager.callKernelAPI(this.pid, 'Network.isOnline', []);

    if (!isOnline) {
        // 离线时提示用户（可以结合 Notification 或对话框）
        console.warn('当前处于离线状态，部分功能不可用');
        // 也可以：弹出通知 / 对话框，提示用户检查网络
    } else {
        console.log('网络已连接:', info);
        // 这里可以触发自动更新检查等逻辑
    }
}
```

要点：  
- `Network.getInfo` 返回的是一个对象，包含当前网络的总体信息（由 `ProcessManager.getNetworkInfo()` 决定具体结构）。  
- `Network.isOnline` 返回当前是否在线的布尔值或类似结果。  

---

## 情景 B：设置界面里的“网络开关”

在“系统设置”里，经常会有一个“启用网络”的开关，用户可以一键打开或关闭网络：

```js
// 设置界面中的事件处理
async function onToggleNetwork() {
    try {
        // 调用 toggle：如果当前是关闭就打开，如果是打开就关闭
        const state = await ProcessManager.callKernelAPI(this.pid, 'Network.toggle', []);
        // state 的返回结构由 ProcessManager.toggleNetwork 决定，通常会包含当前状态
        console.log('网络新状态:', state);
    } catch (e) {
        console.error('切换网络状态失败:', e.message);
    }
}

async function onEnableNetwork() {
    try {
        await ProcessManager.callKernelAPI(this.pid, 'Network.enable', []);
    } catch (e) {
        console.error('启用网络失败:', e.message);
    }
}

async function onDisableNetwork() {
    try {
        await ProcessManager.callKernelAPI(this.pid, 'Network.disable', []);
    } catch (e) {
        console.error('关闭网络失败:', e.message);
    }
}
```

要点：  
- 这些 API 均不需要额外参数（`args` 为 `[]`）。  
- 是否真的能启/停网络，取决于底层实现和权限管理（例如只有管理员或系统层应用可以调用）。

## 情景 C：状态栏显示更详细的连接信息

```js
// 状态栏刷新网络指示灯时调用
async function refreshNetworkIndicator() {
    try {
        const state = await ProcessManager.callKernelAPI(this.pid, 'Network.getState', []);
        const connInfo = await ProcessManager.callKernelAPI(this.pid, 'Network.getConnectionInfo', []);

        // 这里假设 state / connInfo 返回的对象包含如下字段（以实际实现为准）：
        // state: { online: true/false, type: 'wifi' | 'ethernet' | ... }
        // connInfo: { ssid, ip, gateway, dns, ... }

        // 根据 state.online / state.type 决定图标样式
        updateNetworkIcon(state, connInfo);
    } catch (e) {
        console.warn('刷新网络状态失败:', e.message);
        updateNetworkIcon({ online: false }, null);
    }
}
```

这里不强行规定返回结构，而是提醒读者：  
- **以 `ProcessManager.getNetworkState()` 和 `ProcessManager.getNetworkConnectionInfo()` 的实现为准**。  
- 教材关注的是 `callKernelAPI(pid, 'Network.xxx', args)` 的调用方式与典型场景。

---

## 行为小结

| API | 典型 args | 用途 |
|-----|-----------|------|
| `Network.getInfo` | `[]` | 获取整体网络信息（实现自定义） |
| `Network.getState` | `[]` | 获取当前网络状态（在线/离线、类型等） |
| `Network.isOnline` | `[]` | 判断当前是否联网 |
| `Network.getConnectionInfo` | `[]` | 获取更详细的连接信息（如 IP / 网关 / DNS 等） |
| `Network.enable` | `[]` | 尝试启用网络 |
| `Network.disable` | `[]` | 尝试关闭网络 |
| `Network.toggle` | `[]` | 在线/离线状态之间切换 |

通过这几个情景，你可以把 Network 系列 API 理解为“系统级网络总开关 + 状态查询接口”，适合在设置页、状态栏、诊断工具中统一使用。
