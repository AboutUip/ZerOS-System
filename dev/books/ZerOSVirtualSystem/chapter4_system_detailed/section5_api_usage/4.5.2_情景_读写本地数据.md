# 4.5.2 情景：读写本地数据（LocalStorage 与 FileSystem）

## 情景描述

应用需要**持久化一点数据**：例如用户设置、最近打开的文件列表、或草稿。两种常见方式：

1. `LocalStorage`：按 key 存字符串，适合小配置、偏好；需要 `KERNEL_LSTORAGE` 权限。
2. `FileSystem`：读写路径下文件，适合较大或结构化数据（如 JSON 文件）；需要 `KERNEL_DISK_READ` / `KERNEL_DISK_WRITE` 权限。

下面用两个小情景给出**核心代码**，便于直接套用。

---

## 情景 A：用 LocalStorage 存/取“最近使用的路径”

### 前置

- 应用有 `this.pid`，并已具备 `KERNEL_LSTORAGE` 权限。

### 核心代码

```js
const STORAGE_KEY = 'app_last_path';

// 保存
async function saveLastPath(path) {
    await ProcessManager.callKernelAPI(this.pid, 'LocalStorage.set', [STORAGE_KEY, path]);
}

// 读取（不存在则得到 null 或 undefined，需自己判断）
async function loadLastPath() {
    const result = await ProcessManager.callKernelAPI(this.pid, 'LocalStorage.get', [STORAGE_KEY]);
    return result?.data ?? null;
}

// 使用示例
async function onOpenFile(path) {
    await saveLastPath.call(this, path);
    // ... 打开文件逻辑
}

async function init() {
    const last = await loadLastPath.call(this);
    if (last) console.log('上次路径:', last);
}
```

要点：`LocalStorage.set` 的 `args` 是 `[key, value]`（均为字符串）；`LocalStorage.get` 的 `args` 是 `[key]`，返回格式由内核约定（通常通过 `result.data` 取到值）。

---

## 情景 B：用 FileSystem 读/写 JSON 配置

### 前置

- 应用有 `this.pid`；读文件需 `KERNEL_DISK_READ`，写文件需 `KERNEL_DISK_WRITE`。

### 核心代码

```js
const CONFIG_PATH = 'C:/data/myapp_config.json';

// 读取配置（文本）
async function loadConfig() {
    const content = await ProcessManager.callKernelAPI(this.pid, 'FileSystem.read', [CONFIG_PATH]);
    if (!content || typeof content !== 'string') return {};
    try {
        return JSON.parse(content);
    } catch {
        return {};
    }
}

// 写入配置
async function saveConfig(config) {
    const str = JSON.stringify(config, null, 2);
    await ProcessManager.callKernelAPI(this.pid, 'FileSystem.write', [CONFIG_PATH, str]);
}
```

要点：

- `FileSystem.read` 的 `args`：`[path]` 或 `[path, asBase64]`；这里用 `[CONFIG_PATH]` 得到字符串内容。
- `FileSystem.write` 的 `args`：`[path, content]`；`content` 为字符串。若目录不存在，行为取决于内核与底层实现（可能报错或自动创建，以实际实现为准）。
- `FileSystem.exists` 的 `args`：`[path]`；返回 `{ path, exists, type }`，用于在读取前判断文件或目录是否存在，避免把不存在路径当作异常读取。

错误处理可与 4.5.1 类似，用 `try/catch` 捕获权限被拒或路径错误。

---

## 行为小结

| API | 典型 args | 用途 |
|-----|-----------|------|
| `LocalStorage.get` | `[key]` | 按 key 取字符串 |
| `LocalStorage.set` | `[key, value]` | 按 key 存字符串 |
| `FileSystem.read` | `[path]` 或 `[path, asBase64]` | 读文件内容 |
| `FileSystem.write` | `[path, content]` | 写文件内容 |
| `FileSystem.exists` | `[path]` | 判断文件或目录是否存在 |

这样，你就掌握了“小数据用 LocalStorage、文件用 FileSystem”的两种典型用法；其他内核 API 也是 `callKernelAPI(pid, apiName, args)`，按对应 API 的 `args` 顺序传参即可。
