# 4.1.1 EventManager 职责与事件注册

## 本节导读（阅读目标）

本节使读者能够：**① 完全理解 EventManager 的职责：统一事件注册、按 pid 绑定与进程退出时自动清理、优先级与传播控制；② 明确 _eventHandlers、_pidToHandlers、_globalListeners 等内部数据结构及 registerEventHandler 的完整流程；③ 掌握 _interceptAddEventListener 对 document/window/Element 的拦截逻辑与 isKernelModule/isProgramCode 的判定；④ 接手维护时能正确新增事件类型、排查“进程退出后仍触发”或“优先级不符合预期”。** 源码文件：`system/ui/eventManager.js`。

---

## 一、EventManager 的职责与在 MODULE_DEPENDENCIES 中的位置

EventManager 在 BootLoader 的 MODULE_DEPENDENCIES 中依赖 **processManager**；ProcessManager 依赖 memoryManager、kernelMemory 等，因此事件管理器在内核层就绪之后加载。其职责可概括为：

1. **统一事件注册**：提供 `registerEventHandler(pid, eventType, handler, options)`，将“事件类型 + 处理函数”与 **pid** 绑定，支持 priority、selector、stopPropagation、once、passive、useCapture 等选项。
2. **进程退出时自动清理**：当某进程退出时，通过 `unregisterAllByPid(pid)` 移除该 pid 注册的所有处理程序，避免“僵尸监听”与内存泄漏。
3. **传播与优先级**：同一事件类型下，按 priority 数字从小到大依次调用；handler 可返回 `'stop'`/`'stopPropagation'` 或 `'stopImmediate'`/`'stopImmediatePropagation'` 控制传播。
4. **对原生 addEventListener 的监控**：通过 _interceptAddEventListener 包装 document/window/Element 的 addEventListener，内核模块直接放行，程序代码调用时打警告并建议使用 EventManager，便于统一管理与清理。

---

## 二、内部数据结构（源码约 8–66 行）

```javascript
    // 事件处理程序ID计数器，每次 registerEventHandler 自增，用于唯一标识一个注册项
    static _handlerIdCounter = 0;

    // 事件类型 → 处理程序数组（按 priority 排序）
    // 每项: { handlerId, pid, handler, priority, selector, stopPropagation, once, passive }
    static _eventHandlers = new Map();

    // pid → Set<handlerId>，进程退出时据此快速移除该进程所有 handler
    static _pidToHandlers = new Map();

    // 菜单、拖动、拉伸、选择器等专用注册表（与窗口/UI 组件绑定）
    static _registeredMenus = new Map();
    static _registeredDrags = new Map();
    static _registeredResizers = new Map();
    static _registeredSelectors = new Map();

    // 元素级事件：handlerId → { pid, element, eventType, handler, options }
    static _elementEventHandlers = new Map();

    // 全局监听器：每个 eventType 在 document 上只挂载一次，内部按 _eventHandlers 派发
    static _globalListeners = new Map();

    static _initialized = false;
    static _addEventListenerIntercepted = false;
```

**设计原因**：_eventHandlers 按事件类型组织，便于触发时按类型取列表并依优先级执行；_pidToHandlers 按进程组织，便于退出时批量删除；_globalListeners 保证每种事件在 document 上只绑定一个“总分发器”，避免重复绑定与泄漏。

## 三、init 与 _interceptAddEventListener（约 73–247 行）

**init()**：若已初始化则 return；若 document 不可用则打警告并 return；否则调用 _interceptAddEventListener()，并置 _initialized = true。

**_interceptAddEventListener()** 核心逻辑（带注释）：

```javascript
        // 保存原始方法，便于内核模块或最终仍调用原生行为
        const originalDocumentAddEventListener = document.addEventListener;
        const originalWindowAddEventListener = typeof window !== 'undefined' ? window.addEventListener : null;
        const originalElementAddEventListener = Element.prototype.addEventListener;

        if (EventManager._addEventListenerIntercepted) return;
        EventManager._addEventListenerIntercepted = true;

        // 通过 Error().stack 判断调用栈是否包含 kernel/、eventManager.js、guiManager.js 等
        const isKernelModule = () => {
            const stack = new Error().stack || '';
            const kernelPaths = ['kernel/', 'kernel\\', 'eventManager.js', 'taskbarManager.js', 'desktop.js', ...];
            return kernelPaths.some(path => stack.includes(path));
        };

        // 通过调用栈是否包含 service/DISK/D/application/ 等判断是否程序代码
        const isProgramCode = () => {
            const stack = new Error().stack || '';
            const programPaths = ['service/DISK/D/application/', 'service\\DISK\\D\\application\\', ...];
            return programPaths.some(path => stack.includes(path));
        };

        // 替换 document.addEventListener：内核调用直接原样执行；程序调用打 warn 并建议 EventManager.registerEventHandler，再原样执行
        document.addEventListener = function(type, listener, options) {
            if (isKernelModule()) return originalDocumentAddEventListener.call(this, type, listener, options);
            if (isProgramCode()) {
                const pid = EventManager._getCurrentPid();
                KernelLogger.warn("EventManager", `程序 (PID: ${pid}) 直接使用 document.addEventListener 注册 "${type}"，建议使用 EventManager.registerEventHandler() ...`);
            }
            return originalDocumentAddEventListener.call(this, type, listener, options);
        };

        // window.addEventListener、Element.prototype.addEventListener 同理：内核放行，程序打 warn 后仍执行
        // Element 上还会根据事件类型区分“全局冒泡事件”与“非冒泡事件”，分别建议 registerEventHandler(selector) 或 registerElementEvent
```

**行为流程**：init 首次执行时替换 document/window/Element 的 addEventListener；之后任何 addEventListener 调用都会经上述包装——内核路径不写日志，程序路径写建议日志但**不阻止**注册，保证兼容性。

**_getCurrentPid()**（约 254–284 行）：通过 `new Error().stack` 匹配 `service[\/\\]DISK[\/\\][CD][\/\\]application[\/\\]([^\/\\\s]+)` 得到程序名，再在 ProcessManager.PROCESS_TABLE 中查找 programName 对应的 pid；找不到则返回 null。

## 四、registerEventHandler 完整流程（约 306–400+ 行）

```javascript
    static registerEventHandler(pid, eventType, handler, options = {}) {
        // 1. 参数校验：pid 有效、eventType 非空、handler 为函数
        if (!pid || typeof pid !== 'number' || pid <= 0) { KernelLogger.warn(...); return null; }
        if (!eventType || typeof eventType !== 'string' || eventType.trim() === '') { ... return null; }
        if (typeof handler !== 'function') { ... return null; }

        // 2. 权限检查（EXPLOIT_PID 跳过）
        if (typeof PermissionManager !== 'undefined') {
            if (pid !== ProcessManager.EXPLOIT_PID) {
                if (!PermissionManager.hasPermission(pid, PermissionManager.PERMISSION.EVENT_LISTENER)) {
                    KernelLogger.warn("EventManager", `程序 ${pid} 没有权限注册事件处理程序`);
                    return null;
                }
            }
        }

        EventManager.init();

        const { priority = 100, selector = null, stopPropagation = false, once = false, passive = false, useCapture = false } = options;
        const validatedPriority = typeof priority === 'number' && !isNaN(priority) ? priority : 100;

        // 3. 生成 handlerId 并构建 entry
        const handlerId = ++EventManager._handlerIdCounter;
        const entry = { handlerId, pid, handler, priority: validatedPriority, selector, stopPropagation, once, passive, useCapture };

        // 4. 按 eventType 加入 _eventHandlers，并保持按 priority 排序
        if (!EventManager._eventHandlers.has(eventType)) {
            EventManager._eventHandlers.set(eventType, []);
        }
        const list = EventManager._eventHandlers.get(eventType);
        list.push(entry);
        list.sort((a, b) => a.priority - b.priority);

        // 5. 维护 _pidToHandlers
        if (!EventManager._pidToHandlers.has(pid)) {
            EventManager._pidToHandlers.set(pid, new Set());
        }
        EventManager._pidToHandlers.get(pid).add(handlerId);

        // 6. 为该 eventType 确保已绑定全局监听器（只绑定一次）
        EventManager._ensureGlobalListener(eventType, useCapture);

        return handlerId;
    }
```

**行为流程小结**：校验参数 → 权限检查（EVENT_LISTENER）→ init → 生成 handlerId → 写入 _eventHandlers[eventType] 并排序 → 写入 _pidToHandlers[pid] → _ensureGlobalListener(eventType) → 返回 handlerId。

**_ensureGlobalListener**：若 _globalListeners 已有该 eventType，则不重复绑定；否则在 document 上 addEventListener(eventType, 分发函数, useCapture)，分发函数内读取 _eventHandlers.get(eventType)，按顺序调用各 handler，根据返回值决定是否 stopPropagation/stopImmediatePropagation，once 的则在调用后从列表移除。

---

## 五、unregisterEventHandler 与 unregisterAllByPid

- **unregisterEventHandler(handlerId)**：从 _eventHandlers 各列表中移除对应 entry，从 _pidToHandlers 对应 pid 的 Set 中移除 handlerId，从 _elementEventHandlers 移除（若存在）。
- **unregisterAllByPid(pid)**：取 _pidToHandlers.get(pid)，对每个 handlerId 调用 unregisterEventHandler(handlerId)，再 delete _pidToHandlers(pid)。进程退出时由 ProcessManager 或清理逻辑调用，实现“进程退出即清理该进程所有事件”。

---

## 六、行为流程小结（从注册到触发到清理）

1. 程序通过内核 API 调用 `EventManager.registerEventHandler(pid, 'click', handler, { priority: 50 })`。  
2. EventManager 校验 pid/eventType/handler、检查 EVENT_LISTENER 权限、init、生成 handlerId、写入 _eventHandlers['click'] 并排序、写入 _pidToHandlers[pid]、_ensureGlobalListener('click')。  
3. 用户点击页面时，document 上的全局 'click' 监听器被触发，从 _eventHandlers['click'] 按 priority 依次执行 handler；某 handler 返回 'stop' 则后续不再传播。  
4. 进程退出时某处调用 `EventManager.unregisterAllByPid(pid)`，该 pid 下所有 handlerId 被移除，对应条目从 _eventHandlers 中删除，不再被触发。

---

## 七、接手维护要点

- **新增事件类型**：无需在 EventManager 中“声明”类型，只要 registerEventHandler 传入的 eventType 与 document 上 _ensureGlobalListener 绑定的类型一致即可；若使用捕获阶段，需传 useCapture: true。  
- **“进程退出后仍触发”**：确认进程退出路径是否调用了 unregisterAllByPid(pid)；若程序直接使用 document.addEventListener 而未通过 EventManager，则不会被清理，需依赖拦截日志逐步迁移到 registerEventHandler。  
- **优先级不符合预期**：确认 options.priority 为数字且排序规则为“数字小优先”；同一 priority 时顺序为插入顺序，如需稳定顺序可细调 priority 值。  
- **registerElementEvent**：用于在特定元素上绑定不冒泡或需精确 target 的事件（如 mouseenter、load），同样与 pid 绑定，进程退出时需一并清理（通过 _elementEventHandlers 与 pid 的关联）。
