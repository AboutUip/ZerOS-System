# 4.1.3 _ensureGlobalListener 与事件派发算法

## 本节导读（阅读目标）

本节让读者**完完全全参透** EventManager 的**事件派发算法**：每种事件类型（+ useCapture）在 document 或 window 上**只绑定一次**全局监听器（_ensureGlobalListener），该监听器内部通过 **_handleGlobalEvent** 从 _eventHandlers 取出当前类型的处理程序列表、按 **priority 排序**、按 **useCapture 过滤**、再**依次执行**；handler 返回值（'stop'/'stopImmediate' 或 false）如何控制传播与默认行为。学完后能说出“一次 click 从 document 到各 handler 的完整路径”以及“同 eventType 下 useCapture 与 bubble 两套列表如何共存”。源码：`system/ui/eventManager.js` 约 612–720 行。

---

## 一、_ensureGlobalListener 的职责（约 612–666 行）

**目标**：对每个 **(eventType, useCapture)** 组合，在 **document** 或 **window** 上只添加**一个** addEventListener；该监听器内部调用 _handleGlobalEvent(eventType, e, useCapture)，把“实际执行”委托给 _eventHandlers 中注册的 handler 列表。

**键**：`listenerKey = eventType + '_' + useCapture`（例如 "click_false"、"click_true"），保证同一事件类型下**捕获阶段**与**冒泡阶段**各有一份全局监听器。

**目标节点**：resize、focus、blur 在 **window** 上，其余在 **document** 上。

**passive 选项**：若该 eventType 下存在任一 handler 的 passive 为 false，则全局监听器**不用** passive（以便 handler 可调 preventDefault）；否则若事件类型属于 passiveEvents（touchstart、touchmove、wheel 等）或所有 handler 均为 passive，则使用 passive 以优化滚动等性能。

**行为**：若 _globalListeners.has(listenerKey) 已存在则 return；否则创建 globalHandler，target.addEventListener(eventType, globalHandler, { capture: useCapture, passive: shouldBePassive })，并 _globalListeners.set(listenerKey, { listener, useCapture, options, target })。

---

## 二、_handleGlobalEvent 的派发算法（约 674–720+ 行）

1. **取列表**：handlers = _eventHandlers.get(eventType)；若无或空则 return。
2. **按 useCapture 过滤**：matchingHandlers = handlers.filter(h => h.useCapture === useCapture)。即当前是“捕获阶段”触发的全局监听器则只执行 useCapture===true 的 handler；“冒泡阶段”触发的只执行 useCapture===false 的 handler。
3. **创建 eventContext**：{ stopped, prevented, currentHandler, eventType, useCapture }，用于在 handler 间传递“是否已停止传播/已阻止默认”。
4. **按 priority 顺序遍历** matchingHandlers：
   - 若 eventContext.stopped 为 true（且可能是 stopImmediate），则 break，不再执行后续 handler。
   - 若 handler 有 **selector**，则检查 e.target 是否匹配该 selector（或 e.target.closest(selector)）；不匹配则 continue。
   - 调用 **handler(e, eventContext)**；根据返回值：
     - 若为 **'stop' 或 'stopPropagation'**：e.stopPropagation()，eventContext.stopped = true。
     - 若为 **'stopImmediate' 或 'stopImmediatePropagation'**：e.stopImmediatePropagation()，eventContext.stopped = true，并 break 不再执行同列表后续 handler。
     - 若为 **false**：eventContext.prevented = true，e.preventDefault()（若未 passive）。
   - 若 handler 为 **once**，执行后从列表中移除（splice），避免再次触发。
5. 事件继续按浏览器默认行为冒泡或捕获传递（除非已被 stop）。

---

## 三、为何同 eventType 需要两个全局监听器（capture true/false）

因为 **addEventListener 的 capture 参数**决定了该监听器在“捕获阶段”还是“冒泡阶段”被调用；同一事件会先经历“捕获阶段”（从 window 到 target），再“冒泡阶段”（从 target 到 window）。若只绑一个监听器（例如 capture: false），则只会收到冒泡阶段的调用，注册了 useCapture: true 的 handler 就永远不会被调用。因此 EventManager 对每个 (eventType, useCapture) 各绑一个全局监听器，在 _handleGlobalEvent 中再过滤出 matchingHandlers，保证“捕获阶段只执行 useCapture=true 的 handler、冒泡阶段只执行 useCapture=false 的 handler”。

---

## 四、本节小结与维护要点

- 每种 (eventType, useCapture) 对应一个全局监听器；实际执行由 _eventHandlers 中按 priority 排序、按 useCapture 过滤后的列表依次执行；返回值控制 stopPropagation/stopImmediate/preventDefault。
- 排查“某 handler 未触发”：检查是否注册时 useCapture 与期望阶段一致、priority 是否被其他 handler 先执行并 stopImmediate、selector 是否匹配 e.target。
- 同 eventType 下 capture 与 bubble 两套列表通过两个全局监听器与 filter(useCapture) 实现，互不干扰。
