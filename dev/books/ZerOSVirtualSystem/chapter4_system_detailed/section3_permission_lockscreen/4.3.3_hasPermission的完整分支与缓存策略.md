# 4.3.3 hasPermission 的完整分支与缓存策略

## 本节导读（阅读目标）

本节让读者**完完全全参透** PermissionManager.**hasPermission(pid, permission, context)** 的**完整分支逻辑**：EXPLOIT_PID 放行、_ensureInitialized、_permissionCache 的键与 TTL、_permissions 与 _savedPermissionsByProgramName 的查找顺序、以及“自动授予 NORMAL 权限”与“SPECIAL/DANGEROUS 需用户授权”在代码中的分支。学完后能画出 hasPermission 的决策树、说出缓存失效时机、并能排查“权限已授予仍返回 false”。源码：`kernel/process/permissionManager.js` 约 788–950 行。

---

## 一、hasPermission 的入口与 _ensureInitialized（约 788–860 行）

**签名**：`static async hasPermission(pid, permission, context = {})`，返回 `Promise<boolean>`。

**第一步**：`await _ensureInitialized()`。若未初始化则 await init()，保证 _savedPermissionsByProgramName 等已从 LStorage 加载。

**第二步**：**EXPLOIT_PID 放行**。若 `pid === ProcessManager.EXPLOIT_PID`（10000），直接 return true，不查表、不查缓存。

**第三步**：**缓存查找**。cacheKey = `${pid}_${permission}`；若 _permissionCache.has(cacheKey)，取 { result, timestamp }；若 Date.now() - timestamp < CACHE_TTL（5 秒），return result；否则删除该缓存项，继续后续逻辑。

**第四步**：**运行时 _permissions**。若 _permissions.get(pid)?.has(permission) 为 true，则（可选）写入缓存并 return true。

**第五步**：**程序名与 _savedPermissionsByProgramName**。通过 ProcessManager 或进程表取得该 pid 的 programName；若 _savedPermissionsByProgramName.get(programName)?.has(permission) 为 true，则（可选）同步到 _permissions[pid] 并写入缓存，return true。

**第六步**：**权限级别与自动授予**。取 PERMISSION_LEVEL_MAP[permission]；若为 NORMAL 且程序在 __info__.permissions 中声明了该权限，则自动授予：_permissions.get(pid).add(permission)，持久化到 LStorage，写入缓存，return true。

**第七步**：**SPECIAL/DANGEROUS**。若需用户确认或授权，可能进入“权限申请”流程（弹窗、pendingRequests）；若用户同意则授予并 return true，否则 return false；若 context.isRequesting 为 true 表示当前正在请求流程内部，可能递归调用 hasPermission，此时根据“是否已加入 pending 或已拒绝”决定返回。具体以源码为准。

**第八步**：未授予则 return false，并（可选）写入缓存 result: false。

---

## 二、缓存策略与失效

- **键**：`${pid}_${permission}`。
- **TTL**：CACHE_TTL = 5000 毫秒；超时后该键从 _permissionCache 删除，下次 hasPermission 重新计算。
- **失效时机**：用户在某处“撤销权限”或“授予权限”时，应删除对应该 pid 与 permission 的 cacheKey，或调用 clearPermissionCache 等（若存在）；否则 5 秒内仍会返回旧结果。
- **_pendingPermissionChecks**：用于**并发去重**，同一 (pid, permission) 同时多次 hasPermission 时共用一个 Promise，避免重复弹窗或重复查存储。

---

## 三、本节小结与维护要点

- hasPermission 分支顺序：_ensureInitialized → EXPLOIT_PID → 缓存 → _permissions → _savedPermissionsByProgramName → NORMAL 自动授予 → SPECIAL/DANGEROUS 申请流程 → false。
- “权限已授予仍返回 false”：检查缓存是否未失效、programName 是否与保存时一致、init/_loadPermissions 是否已完成（异步）、是否误用了非 POOL 的 Dependency 实例导致查错表。
- 新增权限时在 PERMISSION 与 PERMISSION_LEVEL_MAP 中登记，并确定在哪些内核 API 中调用 hasPermission(pid, permission)。
