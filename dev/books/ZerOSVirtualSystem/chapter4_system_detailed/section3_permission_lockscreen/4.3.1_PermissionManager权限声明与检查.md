# 4.3.1 PermissionManager 权限声明与检查

## 本节导读（阅读目标）

本节使读者能够：**① 完全理解 PermissionManager 的职责：权限枚举 PERMISSION、级别 PERMISSION_LEVEL（NORMAL/SPECIAL/DANGEROUS）、PERMISSION_LEVEL_MAP、按程序名持久化与按 pid 运行时授权；② 明确 hasPermission(pid, permission) 的流程：_ensureInitialized、_permissions 与 _savedPermissionsByProgramName 的配合、EXPLOIT_PID 放行、缓存 _permissionCache 与 CACHE_TTL；③ 掌握 init()、_loadPermissions() 与 LStorage.getSystemStorage('permissionManager.permissions') 的异步加载；④ 接手维护时能正确新增权限项、排查“权限已授予仍返回 false”或“敏感键被普通程序访问”。** 源码文件：`kernel/process/permissionManager.js`。

---

## 一、职责与在依赖图中的位置

PermissionManager 在 MODULE_DEPENDENCIES 中依赖 **filesystem/init** 等（以便 LStorage 可用后加载权限记录）。职责概括：

1. **权限枚举与级别**：PERMISSION 对象列出所有权限常量（如 KERNEL_DISK_READ、SYSTEM_NOTIFICATION、EVENT_LISTENER）；PERMISSION_LEVEL 为 NORMAL（自动授予）、SPECIAL（需用户确认）、DANGEROUS（需明确授权或仅管理员）；PERMISSION_LEVEL_MAP 指定每个权限的级别。
2. **声明与检查**：程序在 __info__.permissions 中声明所需权限；内核 API 在执行敏感操作前调用 `PermissionManager.hasPermission(pid, permission)`，返回 true 才放行。
3. **运行时与持久化**：运行时授权按 pid 存在 _permissions（Map<pid, Set<permission>>）；持久化按**程序名**存在 _savedPermissionsByProgramName，并通过 LStorage.getSystemStorage('permissionManager.permissions') 加载、setSystemStorage 保存，因为 PID 是随机分配的，重启后需按程序名恢复。
4. **EXPLOIT_PID / SERVER_SERVICE_PID**：pid === ProcessManager.EXPLOIT_PID（10000）时跳过权限检查，视为拥有所有权限；D/server 服务调用内核时使用 SERVER_SERVICE_PID，同样放行。
5. **LStorage 敏感键**：LStorage 在读写 system 下敏感键（如 userControl.*、permissionControl.*）时内部会调用 PermissionManager，只有持有对应细粒度权限的进程才能访问，与权限级别 DANGEROUS 及“仅管理员可授予”策略配合。

## 三、init() 与 _loadPermissions()（约 361–456 行）

```javascript
    static async init() {
        if (PermissionManager._initialized) return;
        if (PermissionManager._initPromise) return await PermissionManager._initPromise;

        PermissionManager._initPromise = (async () => {
            try {
                // 等待 LStorage 可用
                if (typeof LStorage !== 'undefined') {
                    let retries = 0;
                    while (retries < 10 && typeof LStorage.getSystemStorage !== 'function') {
                        await new Promise(resolve => setTimeout(resolve, 50));
                        retries++;
                    }
                }
                PermissionManager._initialized = true;
                await PermissionManager._loadPermissions();
                PermissionManager._loadDenialCounts().catch(...);
                PermissionManager._startCleanupTimer();
            } catch (e) {
                KernelLogger.error(...);
                PermissionManager._initialized = true;
            } finally {
                PermissionManager._initPromise = null;
            }
        })();
        return await PermissionManager._initPromise;
    }

    static async _loadPermissions() {
        if (typeof LStorage === 'undefined') return;
        const saved = await LStorage.getSystemStorage('permissionManager.permissions');
        if (saved && typeof saved === 'object') {
            for (const [programName, permissions] of Object.entries(saved)) {
                if (/^\d+$/.test(programName)) continue;  // 跳过旧格式 PID 键
                if (typeof programName === 'string' && Array.isArray(permissions)) {
                    PermissionManager._savedPermissionsByProgramName.set(programName, new Set(permissions));
                }
            }
        }
    }
```

**行为流程**：init 只执行一次，通过 _initPromise 串行化；等待 LStorage.getSystemStorage 可用后，从 'permissionManager.permissions' 加载按程序名保存的权限集合到 _savedPermissionsByProgramName；进程启动时根据 programName 从 _savedPermissionsByProgramName 恢复到 _permissions[pid]。

## 四、hasPermission(pid, permission) 流程

1. **_ensureInitialized()**：若未初始化则 await init()。  
2. **EXPLOIT_PID 放行**：若 pid === ProcessManager.EXPLOIT_PID，直接返回 true。  
3. **缓存**：键为 `${pid}_${permission}`，若 _permissionCache 中存在且未过期（CACHE_TTL），返回缓存结果。  
4. **运行时 _permissions**：若 _permissions.get(pid)?.has(permission) 为 true，返回 true。  
5. **程序名与 _savedPermissionsByProgramName**：通过 ProcessManager 或进程表取得该 pid 的 programName，若 _savedPermissionsByProgramName.get(programName)?.has(permission) 为 true，返回 true（并可选写入 _permissions[pid] 以加速后续）。  
6. **级别与自动授予**：若该权限为 NORMAL 且程序在 __info__.permissions 中声明了该权限，可自动授予并写入 _permissions 与持久化，返回 true。  
7. **否则**：若为 SPECIAL/DANGEROUS 且未授予，可触发权限申请流程（弹窗等）；未授予则返回 false，并记录 _permissionDenialCount，达到 MAX_DENIAL_COUNT 后不再弹窗。

---

## 五、行为流程小结

1. 系统启动后 PermissionManager.init() 被调用，_loadPermissions() 从 LStorage 加载按程序名保存的权限。  
2. 程序启动时，根据其 __info__.permissions 与已保存的权限，为该 pid 填充 _permissions[pid]。  
3. 内核 API 在执行前调用 hasPermission(pid, permission)；EXPLOIT_PID 放行，否则查缓存、_permissions、_savedPermissionsByProgramName 与级别策略，返回 true/false。  
4. 用户授权或自动授予后，更新 _permissions 并持久化到 LStorage。

---

## 六、接手维护要点

- **新增权限**：在 PERMISSION 中增加常量，在 PERMISSION_LEVEL_MAP 中指定 NORMAL/SPECIAL/DANGEROUS；在需要检查的内核 API 中调用 hasPermission(pid, permission)。  
- **“权限已授予仍返回 false”**：确认持久化键为 'permissionManager.permissions' 且按程序名存储；确认进程的 programName 与保存时一致；确认 init() 与 _loadPermissions() 已完成后再做检查（异步需 await）。  
- **敏感键与 LStorage**：LStorage 内部对 userControl.*、permissionControl.* 等键的访问会校验对应细粒度权限（如 SYSTEM_STORAGE_READ_USER_CONTROL），只有管理员授予的进程可访问；普通程序只能访问非敏感 system 键。
