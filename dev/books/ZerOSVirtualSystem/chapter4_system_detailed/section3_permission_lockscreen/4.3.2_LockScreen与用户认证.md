# 4.3.2 LockScreen 与用户认证

## 本节导读（阅读目标）

本节使读者能够：**① 理解 LockScreen 的职责：锁屏容器、用户列表、密码输入与校验、登录成功后隐藏锁屏；② 明确 init() 中安全模式检查（sessionStorage __ZEROS_SAFE_MODE__）、_setBackground、_createLockScreenContent、_setupKeyboardListeners；③ 掌握 _getText 与 LanguagesExpansion、与 UserControl/LStorage 的认证对接；④ 接手维护时能正确扩展锁屏样式或排查“安全模式下仍显示锁屏”。** 源码文件：`system/ui/lockscreen.js`。

---

## 一、职责与依赖

LockScreen 依赖 **LanguagesExpansion**（多语言）、与用户认证相关的 **UserControl** 或 LStorage（存储用户与密码校验结果）。职责概括：

1. **锁屏界面**：在内核与系统层加载完成后显示全屏锁屏容器（#lockscreen），覆盖桌面与任务栏，直到用户完成认证。
2. **用户选择与密码**：展示用户列表（_userList）、当前用户（currentUser）；用户输入密码后点击登录，调用认证接口（如 UserControl 或后端）校验，成功则隐藏锁屏并允许进入系统。
3. **安全模式**：若 sessionStorage 中 __ZEROS_SAFE_MODE__ === 'true'，init() 直接 return，不创建锁屏，便于维护与恢复。
4. **多语言**：界面文案通过 _getText(key, fallback) 使用 LanguagesExpansion.getText，语言切换后需刷新锁屏文案（若有语言切换监听）。

## 三、init() 流程（约 55–100 行）

```javascript
    static async init() {
        if (LockScreen._initialized) return;
        // 安全模式：sessionStorage __ZEROS_SAFE_MODE__ === 'true' 则跳过
        let isSafeMode = false;
        try {
            if (typeof sessionStorage !== 'undefined') {
                isSafeMode = sessionStorage.getItem('__ZEROS_SAFE_MODE__') === 'true';
            }
        } catch (e) {}
        if (isSafeMode) {
            KernelLogger.info("LockScreen", "安全模式已启用，跳过锁屏界面初始化");
            return;
        }
        LockScreen._initialized = true;
        LockScreen.container = document.createElement('div');
        LockScreen.container.id = 'lockscreen';
        await LockScreen._setBackground();
        await LockScreen._createLockScreenContent();
        document.body.appendChild(LockScreen.container);
        LockScreen._setupKeyboardListeners();
        LockScreen._updateTime();
        LockScreen._updateUserInfo();
        // ...
    }
```

**行为流程**：已初始化或安全模式则直接 return；否则创建容器、设置背景、创建内容（用户列表、密码框、登录按钮）、挂载到 body、绑定键盘与时间/用户信息更新。

---

## 四、认证与登录成功

密码校验通常由 UserControl 或后端接口完成；校验成功后：

1. 将“已登录”状态写入 LStorage 或 sessionStorage。  
2. 隐藏或移除 LockScreen.container（如 display: none 或 remove），使桌面与任务栏可见。  
3. 可选：触发“登录成功”事件供其他模块（如桌面、任务栏）刷新用户相关 UI。

---

## 五、接手维护要点

- **“安全模式下仍显示锁屏”**：确认在进入安全模式的路径上正确设置了 sessionStorage.setItem('__ZEROS_SAFE_MODE__', 'true')，且 LockScreen.init() 在该之后执行；若 LockScreen 先于安全模式标志设置则可能已创建锁屏，可在 init 开头再次读取 sessionStorage 并若为安全模式则移除已创建的 container。  
- **扩展锁屏样式**：修改 lockscreen 的 class 或内联样式、主题变量；多语言在 _createLockScreenContent 中使用 _getText。
