# 4.4.2 LanguagesExpansion 与 SystemExpansion

## 本节导读（阅读目标）

本节使读者能够：**① 完全理解 LanguagesExpansion 的职责：语言包目录 D/plugins、LANG_STORAGE_KEY、getText(key)、当前语言持久化与恢复、_ready；② 明确 getNodeTreeForLangPacks、readLangPackFile、FSDirve 回退与 PHP 的配合；③ 理解 SystemExpansion 的职责：全屏 SystemProtocol/SystemPatch/SystemConfiguration、_checkCaller 仅允许 D/server 或 terminal；④ 接手维护时能正确新增语言包或扩展系统协议类型。** 源码文件：`system/expansion/languagesExpansion.js`、`system/expansion/systemExpansion.js`。

---

## 一、LanguagesExpansion 职责与数据结构

- **语言包目录**：D 盘下 plugins（即 D/plugins 或 D:/plugins），通过 Disk.diskSeparateMap 取 D 或 D: 的 NodeTreeCollection，路径为 nodeTree.separateName + '/' + LANG_PACKS_DIR。
- **当前语言**：持久化键为 LANG_STORAGE_KEY（'languagesExpansion'），存在 LStorage；启动时恢复当前语言并加载对应语言包 JSON（如 zh-CN.json）。
- **getText(key)**：根据当前语言从已加载的语言包对象中取 key 对应文案；若无则返回 key 或空；供 TaskbarManager、NotificationManager、LockScreen 等 _getText(key, fallback) 内部调用。
- **_ready**：在从 LStorage 恢复当前语言并加载语言包后 resolve，供 start_init 等待。

---

## 二、getNodeTreeForLangPacks 与 readLangPackFile（languagesExpansion.js 约 22–57 行）

```javascript
    function getNodeTreeForLangPacks() {
        if (typeof Disk === 'undefined') return null;
        let map = Disk.diskSeparateMap;
        if (!map) return null;
        let nodeTree = map.get('D') || map.get('D:') || null;
        if (!nodeTree) return null;
        let packsPath = nodeTree.separateName + '/' + LANG_PACKS_DIR;
        return { nodeTree, packsPath };
    }

    async function readLangPackFile(fileName) {
        let ref = getNodeTreeForLangPacks();
        if (!ref || !ref.nodeTree.initialized) return null;
        if (ref.nodeTree.hasNode && !ref.nodeTree.hasNode(ref.packsPath)) return null;
        try {
            let content = await ref.nodeTree.read_file(ref.packsPath, fileName);
            return content != null ? String(content) : null;
        } catch (e) {
            return null;
        }
    }
```

**行为流程**：从 Disk 取 D 分区 NodeTree，拼接 plugins 路径；readLangPackFile 在该路径下读取 fileName（如 zh-CN.json），若 D 或 plugins 未就绪则返回 null，上层可走 FSDirve/PHP 回退。

## 三、SystemExpansion 职责与 _checkCaller（systemExpansion.js 约 12–79 行）

- **VALID_TYPES**：'SystemProtocol'、'SystemPatch'、'SystemConfiguration'，对应全屏显示的协议/补丁/配置界面。  
- **_checkCaller()**：通过 new Error().stack 检查调用栈；若包含 `system/service/DISK/D/server/` 或 terminal/debug 则允许；否则打警告并 return false。即仅 D/server 下服务或终端可调用 SystemExpansion 的全屏接口，防止普通应用滥用。  
- **SYSTEM_PID**：ProcessManager.SERVER_SERVICE_PID（10000），与 EXPLOIT_PID 一致，服务调用时使用该 PID 放行权限。

---

## 四、行为流程小结

1. **LanguagesExpansion**：init 或首次 getText 时从 LStorage 读当前语言，从 D/plugins 或 FSDirve 加载对应 JSON，填充语言包对象，resolve _ready；getText(key) 从语言包对象取 key。  
2. **SystemExpansion**：D/server 某服务或 terminal 调用全屏接口时，_checkCaller 通过则显示对应类型全屏页，用户点击“完成”或“取消”后关闭并可选 resolve _ready。

---

## 五、接手维护要点

- **新增语言包**：在 D/plugins 下增加 xx-YY.json，格式与现有一致（key → 文案）；在 LanguagesExpansion 当前语言列表中增加选项，恢复与保存时使用 LANG_STORAGE_KEY。  
- **新增 SystemExpansion 类型**：在 VALID_TYPES 与 TYPE_BUTTON_LABELS、TYPE_ICONS 中增加新类型，在全屏渲染与按钮逻辑中分支处理。
