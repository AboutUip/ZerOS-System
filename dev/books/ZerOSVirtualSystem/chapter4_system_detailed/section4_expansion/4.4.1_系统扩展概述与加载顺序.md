# 4.4.1 系统扩展概述与加载顺序

## 本节导读（阅读目标）

本节使读者能够：**① 理解“系统扩展”在 ZerOS 中的含义：在 MODULE_DEPENDENCIES 中依赖 filesystem/init（或 kernel 基础）的模块，在 start_init 中 loadModules 之后被加载；② 明确 start_init 中 await LanguagesExpansion._ready、await SystemExpansion._ready 等与扩展模块 _ready Promise 的配合；③ 掌握各扩展的职责边界与依赖关系；④ 接手维护时能正确新增扩展或调整加载顺序。** 源码位置：`bootloader/starter.js`（start_init）、各 `system/expansion/*.js`。

---

## 一、扩展在 MODULE_DEPENDENCIES 中的位置

在 starter.js 的 MODULE_DEPENDENCIES 中，扩展模块通常依赖 **../kernel/filesystem/init.js**（或 disk、nodeTree、fileFramework），以保证在文件系统就绪后加载。例如：

- **languagesExpansion.js**：依赖 init.js，提供语言包加载、当前语言设置、getText(key)。
- **serverExpansion.js**：依赖 init.js，提供 D/server 服务的启动/停止/查询等，供 ProcessManager 暴露的 Server.* API 使用。
- **systemExpansion.js**：依赖 init.js，提供全屏系统协议/补丁/配置界面，仅允许 D/server 或特定调用来源。
- **wasmExpansion.js**、**nodeLibExpansion.js**：依赖 init.js，提供 Wasm 与 Node 兼容库能力。

因此加载顺序为：init（及 disk、nodeTree、fileFramework）→ 各扩展；扩展之间若有依赖，需在 MODULE_DEPENDENCIES 中声明（如某扩展依赖 languagesExpansion）。

---

## 二、start_init 中对 _ready 的等待（starter.js 约 1172–1189 行）

```javascript
            await loadModules(MODULE_DEPENDENCIES);

            if (typeof LanguagesExpansion !== 'undefined' && LanguagesExpansion._ready) {
                await LanguagesExpansion._ready;
            }
            if (typeof SystemExpansion !== 'undefined' && SystemExpansion._ready) {
                await SystemExpansion._ready;
            }
            // ...
```

loadModules 会按拓扑序加载并执行各脚本；执行后各扩展模块会暴露 _ready（Promise）。start_init 在 loadModules 完成后 await 这些 _ready，确保“语言包已从 LStorage 恢复并加载”“系统扩展已就绪”等再继续后续步骤（如 ExceptionHandler 检查、锁屏等）。

---

## 三、扩展的 _ready 约定

- **LanguagesExpansion**：在从 LStorage 恢复当前语言并加载对应语言包后 resolve _ready（或 _ready 在首次 getText 前 resolve）。  
- **SystemExpansion**：若需显示全屏协议/配置，可在首次显示完成或用户确认后 resolve _ready；若无则初始化完成即 resolve。  
- 其他扩展若需“就绪”信号，可同样暴露 _ready = new Promise(...)，在初始化完成时 resolve，并在 start_init 中增加 await 该扩展._ready（若存在）。

---

## 四、行为流程小结

1. BootLoader 执行 loadModules(MODULE_DEPENDENCIES)，按拓扑序加载 init 与各扩展脚本。  
2. 各扩展脚本执行后，创建 _ready Promise 并在异步初始化完成时 resolve。  
3. start_init 在 loadModules 之后 await LanguagesExpansion._ready、SystemExpansion._ready 等。  
4. 全部就绪后继续内核自检、锁屏等后续流程。

---

## 五、接手维护要点

- **新增扩展**：在 MODULE_DEPENDENCIES 中增加新模块路径并声明对 init 或其它扩展的依赖；若需被 start_init 等待，暴露 _ready 并在 start_init 中 await。  
- **调整顺序**：修改 MODULE_DEPENDENCIES 中依赖关系即可改变拓扑序；注意循环依赖会被拓扑排序检测并报错。
