# 4.2.2 NotificationManager 与通知显示

## 本节导读（阅读目标）

本节使读者能够：**① 理解 NotificationManager 的职责：通知的显示、队列、动画、位置与任务栏位置联动；② 明确 CONFIG、_notifications、_notificationIdCounter 及 show()/dismiss() 的流程；③ 掌握权限 SYSTEM_NOTIFICATION、多语言 _getText 与 LanguagesExpansion；④ 接手维护时能正确扩展通知样式或排查“通知不显示/不消失”。** 源码文件：`system/ui/notificationManager.js`。

---

## 一、职责与依赖

NotificationManager 依赖 **taskbarManager**、**processManager**、**eventManager**。职责概括：

1. **显示通知**：程序通过内核 API（需 SYSTEM_NOTIFICATION 权限）调用 NotificationManager.show(options)，传入 title、body、icon、duration 等；NotificationManager 分配 notificationId，将通知加入 _notifications，在 _notificationContainer 中渲染一条通知条目，并播放显示动画（CONFIG.ANIMATION.SHOW_DURATION）。
2. **队列与数量**：多条通知按到达顺序排列；容器宽度、位置、z-index 由 CONFIG 控制，与任务栏位置（_getTaskbarPosition）联动，避免被任务栏遮挡。
3. **自动关闭与手动关闭**：duration 毫秒后自动 dismiss；用户点击关闭按钮或交互逻辑调用 dismiss(id) 移除该条并播放隐藏动画。
4. **多语言**：空状态等文案通过 _getText(key, fallback) 使用 LanguagesExpansion.getText，语言切换时 _refreshUIStrings() 更新。


---

## 三、show() 与 dismiss() 流程

- **show(options)**：init() 确保容器已创建；++_notificationIdCounter 作为 id；将 { id, title, body, icon, duration, ... } 存入 _notifications；在 _notificationContainer 中插入 DOM 节点，应用样式与动画；若 options.duration > 0，setTimeout 后调用 dismiss(id)。
- **dismiss(id)**：从 _notifications 删除，从 DOM 移除对应节点，播放隐藏动画；若 _notifications.size === 0 可隐藏容器或显示空状态。

---

## 四、行为流程小结

1. 程序调用 show({ title, body, duration })；NotificationManager 分配 id、写入 _notifications、渲染 DOM、启动定时 dismiss。  
2. 用户点击关闭或定时到达时 dismiss(id)，从 _notifications 与 DOM 移除。  
3. 任务栏位置变化时，通知容器位置/边距需根据 _getTaskbarPosition() 调整，避免与任务栏重叠。

---

## 五、接手维护要点

- **“通知不显示”**：确认程序已获 SYSTEM_NOTIFICATION 权限（PermissionManager.hasPermission(pid, SYSTEM_NOTIFICATION)）；确认 NotificationManager.init() 已执行且 _notificationContainer 已挂载到 document。  
- **“通知不消失”**：确认 duration 有效且 setTimeout 调用了 dismiss；若 duration 为 0 或未传，需手动 dismiss 或扩展为“常驻直到用户关闭”。  
- **扩展样式**：在 CONFIG.STYLES 或具体 DOM 类名中增加样式；动画时长在 CONFIG.ANIMATION 中统一配置。
