# 4.2.1 TaskbarManager 与进程图标

## 本节导读（阅读目标）

本节使读者能够：**① 理解 TaskbarManager 的职责：任务栏渲染、运行中进程图标、开始菜单、与 ProcessManager/GUIManager 的协作；② 明确 update() 与 PROCESS_TABLE 的同步、_renderInProgress/_pendingUpdate 防并发、单窗口预览与 GUIManager.getTaskbarPreviewProvider(pid)；③ 掌握任务栏位置、多语言 _getText 与 LanguagesExpansion 的配合；④ 接手维护时能正确扩展任务栏项、排查“进程已退出图标仍显示”或“预览不更新”。** 源码文件：`system/ui/taskbarManager.js`。

---

## 一、职责与依赖

TaskbarManager 依赖 **processManager**、**applicationAssetManager**、**contextMenuManager**、**eventManager**、**programCategories**、**themeManager**、**volumeManager**。职责概括：

1. **任务栏 DOM 与布局**：渲染任务栏容器、开始按钮、运行中程序图标区、系统托盘区（时间、音量、电池等）、任务栏位置（bottom/left/right/top）由配置或 LStorage 读取。
2. **运行中进程图标**：通过 ProcessManager.PROCESS_TABLE（或受保护进程表）获取当前运行中的进程，为每个 pid 渲染一个图标；图标点击可聚焦该进程窗口或显示单窗口预览（由 GUIManager.getTaskbarPreviewProvider(pid) 提供内容）。
3. **开始菜单**：点击开始按钮展开开始菜单，显示常显程序、最近使用（RECENT_PROGRAMS_KEY）、搜索、电源选项等；多语言通过 LanguagesExpansion.getText 与 _getText(key, fallback) 获取。
4. **与 GUIManager 的协作**：单窗口预览时，TaskbarManager 调用 GUIManager.getTaskbarPreviewProvider(pid) 得到 { getPreviewContent, onPreviewClick }，用 getPreviewContent() 的返回值（string 或 HTMLElement）渲染预览区域，点击时触发 onPreviewClick。

## 三、update() 与进程表同步

任务栏需要与 ProcessManager 的进程表保持同步：进程启动时出现图标，进程退出时移除图标。典型流程：

1. **定时或事件驱动更新**：通过 setInterval 或 ProcessManager/事件回调调用 `TaskbarManager.update()`。
2. **update()**：若 _renderInProgress 为 true，则置 _pendingUpdate = true 并 return；否则置 _renderInProgress = true，读取 ProcessManager.PROCESS_TABLE（或通过安全接口获取运行中 pid 列表），与当前已渲染的图标对比，增删或更新 DOM，最后置 _renderInProgress = false，若 _pendingUpdate 为 true 则再执行一次 update() 并清空 _pendingUpdate。

这样避免在单次渲染过程中再次触发渲染导致重复或错乱。

---

## 四、单窗口预览与 GUIManager

当用户悬停某进程的任务栏图标时，若该进程仅有一个窗口且已注册预览提供者，则显示预览浮层。流程：

1. TaskbarManager 从 GUIManager.getTaskbarPreviewProvider(pid) 获取 provider。
2. 若 provider 存在且 getPreviewContent 为函数，调用 getPreviewContent() 得到 string 或 HTMLElement，插入预览容器并显示。
3. 用户点击预览区域时，若 provider.onPreviewClick 存在则调用 onPreviewClick(event)。

程序通过内核 API 调用 GUIManager.registerTaskbarPreviewProvider(pid, { getPreviewContent, onPreviewClick }) 注册；进程退出时应调用 GUIManager.unregisterTaskbarPreviewProvider(pid)，否则 TaskbarManager 可能仍持有过期的 provider 引用。

---

## 五、行为流程小结

1. 系统启动后 TaskbarManager.init() 或首次需要时渲染任务栏 DOM，并启动定时或事件驱动的 update()。  
2. update() 读取进程表，为每个运行中 pid 渲染/更新图标；点击图标聚焦窗口或显示预览。  
3. 进程退出时 ProcessManager 更新进程表，下次 update() 时该 pid 不再在表中，对应图标被移除；若未调用 unregisterTaskbarPreviewProvider，预览逻辑可能仍尝试 getPreviewContent(pid)。

---

## 六、接手维护要点

- **“进程已退出图标仍显示”**：确认 update() 的数据源与 ProcessManager 的进程表一致（包括 status 为 exited 的进程是否被过滤）；确认退出路径会触发一次 update() 或定时器足够频繁。  
- **“预览不更新”**：getPreviewContent 应由程序在内容变化时返回最新内容；若程序不更新，TaskbarManager 可在每次悬停时重新调用 getPreviewContent() 已是最新。  
- **扩展任务栏项**：在任务栏 DOM 结构中增加新区域，在 update() 或专门方法中根据配置/状态渲染；多语言统一用 _getText(key, fallback)。
