# 2.2.2 等待与就绪接口

## 本节导读

DependencyConfig 提供异步的 **waitLoaded** 与同步的 **waitLoadedSync**，供 BootLoader 或其它模块等待某依赖项变为“已加载”（loaded 为 true）。本节深入到**源码**（`kernel/core/signal/dependencyConfig.js` 第 46–120 行）：逐段解析两个接口的实现、参数含义、以及 waitLoaded 的轮询与超时逻辑；并说明 BootLoader 中如何调用、为何 RandomSecurity 使用长超时而普通模块使用短超时。

---

## 一、waitLoaded(name, options) — 异步等待（第 49–79 行）

### 1.1 签名与参数

```javascript
waitLoaded(name, options = {}) {
    const interval = typeof options.interval === "number" ? options.interval : 50;
    const timeout = typeof options.timeout === "number" ? options.timeout : 5000;
```

- **name**：模块路径或名称，与 dependencyMap 的键一致。
- **options.interval**：轮询间隔（毫秒），默认 50。每隔 interval ms 检查一次 entry.loaded。
- **options.timeout**：总等待时间（毫秒），默认 5000。超时后 reject，避免无限等待。

### 1.2 已加载则立即 resolve

```javascript
    return new Promise((resolve, reject) => {
        const entry = this.dependencyMap.get(name);
        if (entry && entry.loaded) {
            KernelLogger.info("DependencyConfig", `等待完成: ${name}`);
            return resolve(true);
        }
```

若当前 entry 已存在且 loaded 为 true，直接 resolve(true)，不启动定时器。

### 1.3 轮询与超时

```javascript
        const start = Date.now();
        const timer = setInterval(() => {
            const e = this.dependencyMap.get(name);
            if (e && e.loaded) {
                clearInterval(timer);
                KernelLogger.info("DependencyConfig", `等待完成: ${name}`);
                return resolve(true);
            }
            if (Date.now() - start >= timeout) {
                clearInterval(timer);
                KernelLogger.error("DependencyConfig", `等待超时: ${name} 加载失败`);
                return reject(new Error(`waitLoaded: timeout waiting for "${name}"`));
            }
        }, interval);
    });
}
```

- 使用 setInterval 每隔 interval 毫秒执行一次回调。
- 每次检查：若 entry 存在且 loaded 为 true，则 clearInterval、resolve(true)。
- 若已超过 timeout 毫秒仍未 loaded，则 clearInterval、打错误日志、reject(new Error(...))。
- 注意：没有在 resolve/reject 后清除 timer 的多余逻辑，因为 clearInterval 已在两处分支中调用，保证只 resolve 或 reject 一次。

**为什么用轮询而不是事件？** 当前实现依赖“模块主动 publishSignal”，若改为事件驱动，需要 dependencyLoaded 事件携带 name，且等待方注册一次性的 listener；轮询实现简单，且与现有“依赖 map 状态”的模型一致。轮询间隔不宜过小，避免占用主线程，50ms 是折中。

## 二、waitLoadedSync(name, options) — 同步等待（第 86–120 行）

### 2.1 签名与已加载检查

```javascript
waitLoadedSync(name, options = {}) {
    const interval = typeof options.interval === "number" ? options.interval : 10;
    const timeout = typeof options.timeout === "number" ? options.timeout : 5000;

    KernelLogger.info("DependencyConfig", `同步等待加载: ${name}`);

    const entry = this.dependencyMap.get(name);
    if (entry && entry.loaded) {
        KernelLogger.info("DependencyConfig", `同步等待完成: ${name}`);
        return true;
    }
```

参数与 waitLoaded 类似，interval 默认 10ms（更短，因为同步等待通常用于关键路径、希望尽快返回）。若已 loaded 直接返回 true。

### 2.2 同步阻塞轮询与 busy-wait

```javascript
    const start = Date.now();
    while (true) {
        const e = this.dependencyMap.get(name);
        if (e && e.loaded) {
            KernelLogger.info("DependencyConfig", `同步等待完成: ${name}`);
            return true;
        }

        if (Date.now() - start >= timeout) {
            KernelLogger.error("DependencyConfig", `同步等待超时: ${name} 加载失败`);
            return false;
        }

        const endTime = Date.now() + interval;
        while (Date.now() < endTime) {
            // busy-wait
        }
    }
}
```

- 在 while(true) 中反复检查 entry.loaded；若超时则返回 false。
- “等待 interval 毫秒”通过 **busy-wait**（空循环直到 Date.now() >= endTime）实现，因此会**阻塞主线程**。注释也注明“只用于关键模块”。在浏览器中长时间同步等待会卡住 UI，故 BootLoader 主要使用异步 waitLoaded。

---

## 三、BootLoader 中的使用方式

在 starter.js 中：

1. **RandomSecurity**：`await Dependency.waitLoaded(RANDOM_SECURITY_MODULE, { timeout: 15000 })`。安全校验可能涉及网络请求（如 JWT），耗时较长，故给 15 秒；且必须等其 loaded 后再继续 loadModules，否则后续模块可能依赖未就绪的安全环境。
2. **每个模块加载后（可选）**：`await Dependency.waitLoaded(module, { interval: 10, timeout: 2000 })`。给 2 秒让模块执行 IIFE 并 publishSignal；若模块未发布信号则超时后 catch 继续，避免整层卡死。interval 较小以便更快感知就绪。

---

## 四、本节小结

- **waitLoaded**：Promise 式异步等待，通过 setInterval 轮询 entry.loaded，超时 reject；interval 默认 50ms，timeout 默认 5000ms。
- **waitLoadedSync**：同步阻塞，while + busy-wait 轮询，超时返回 false；会阻塞主线程，仅适合关键、短时等待。
- BootLoader 对 RandomSecurity 使用长超时 waitLoaded，对普通模块使用短超时 waitLoaded 并 catch 超时继续，兼顾安全校验必须完成与普通模块可能未发信号的兼容性。
