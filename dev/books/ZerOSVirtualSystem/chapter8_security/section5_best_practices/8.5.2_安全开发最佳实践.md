# 8.5.2 安全开发最佳实践

## 本节导读

本节使读者能够：**① 掌握安全开发的核心原则；② 理解常见安全问题的预防措施；③ 能够在日常开发中应用安全实践。**

---

## 一、安全开发原则

### 1.1 最小权限原则

每个组件只应拥有完成其任务所需的最小权限：

```javascript
// 不好：权限过大
const program = {
    permissions: ['KERNEL_DISK_READ', 'KERNEL_DISK_WRITE', 'KERNEL_DISK_DELETE', 'PROCESS_MANAGE']
};

// 好：按需授权
const program = {
    permissions: ['KERNEL_DISK_READ', 'KERNEL_DISK_WRITE']
};
```

### 1.2 防御深度原则

多层防御，即使一层被突破也有其他层保护：

```javascript
// 多层验证
async function writeFile(path, content) {
    // 第1层：权限检查
    if (!hasPermission('KERNEL_DISK_WRITE')) {
        throw new Error('无权限');
    }
    
    // 第2层：路径验证
    if (!validatePath(path)) {
        throw new Error('无效路径');
    }
    
    // 第3层：敏感文件检查
    if (isSensitiveFile(path)) {
        if (!isSystemToken()) {
            throw new Error('禁止写入敏感文件');
        }
    }
    
    // 执行写入
    await doWrite(path, content);
}
```

### 1.3 默认安全原则

系统默认应该是安全的，不应该依赖用户配置：

```javascript
// 默认不允许访问
const defaultPermissions = {
    disk: { read: false, write: false, delete: false },
    network: { access: false }
};
```

## 二、常见问题预防

### 2.1 输入验证

```javascript
// 验证所有输入
function validatePath(path) {
    // 类型检查
    if (typeof path !== 'string') return false;
    
    // 格式检查
    if (!/^[A-Z]:/.test(path)) return false;
    
    // 路径穿越检查
    if (path.includes('..')) return false;
    
    return true;
}
```

### 2.2 敏感数据处理

```javascript
// 不在日志中记录敏感信息
function logOperation(operation, data) {
    const safeData = { ...data };
    delete safeData.password;
    delete safeData.token;
    
    Logger.info(operation, safeData);
}
```

### 2.3 安全编码

```javascript
// 防止 XSS
function escapeHtml(text) {
    const div = document.createElement('div');
    div.textContent = text;
    return div.innerHTML;
}
```

## 三、开发 checklist

- [ ] 所有 API 都有权限检查吗？
- [ ] 用户输入都有验证吗？
- [ ] 敏感数据被妥善处理吗？
- [ ] 错误信息不暴露敏感细节吗？
- [ ] 日志不包含敏感信息吗？
- [ ] 第三方依赖及时更新了吗？

---

## 本节小结

1. **最小权限**：只授予必要权限
2. **防御深度**：多层验证
3. **默认安全**：不依赖用户配置
