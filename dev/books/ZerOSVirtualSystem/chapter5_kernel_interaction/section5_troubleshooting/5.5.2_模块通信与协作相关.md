# 5.5.2 模块通信与协作相关

## 本节导读（阅读目标）

本节汇总与 **POOL、KernelMemory、事件、ProcessManager 与 MemoryManager、GUIManager 与 EventManager、PermissionManager 与 LStorage、BootLoader 与 DependencyConfig/POOL** 相关的常见错误与排查思路。

---

## 一、POOL

| 现象 | 可能原因 | 排查与解决 |
|------|----------|------------|
| 取到 undefined | 尚未注册或类别/名称写错 | 确认注册方已执行且类别、名称与注册时完全一致（区分大小写）；必要时在获取前 waitForCoreModules 或等待 dependencyLoaded |
| 取到 { isInit: true } 且无业务对象 | 该类别已 __INIT__ 但尚未 __ADD__ 具体 name | 检查加载顺序，确保提供方模块先于使用方执行并完成 __ADD__ |
| 调用取到的对象时报错“不是函数” | 注册的是类而非实例，或注册错了引用 | 确认注册的是调用方期望的类型（单例实例 vs 类）；检查 __ADD__ 的第三个参数 |
| 多分区下取错 NodeTree | 分区名不一致（如 "C" vs "C:"） | 使用与 Disk 一致的规范化盘符（如 ProcessManager._normalizeDiskName），并在注册与获取时统一 |

---

## 二、KernelMemory

| 现象 | 可能原因 | 排查与解决 |
|------|----------|------------|
| loadData 返回 undefined | key 从未 saveData，或 key 拼写不一致 | 确认写入方已调用 saveData(key, data)；检查 key 字符串是否与写入方完全一致 |
| saveData 后刷新丢失 | 数据未真正写入 Exploit 持久化区域，或 Exploit 内存未正确初始化 | 确认 _ensureMemory 已成功、MemoryManager 已就绪；检查 APPLICATION_SOP 中 EXPLOIT_PID 分区是否存在 |
| 多模块写同一 key 导致覆盖 | 违反“单写方”约定 | 约定每个 key 仅由一个模块写入；其他模块只读或通过负责方 API 访问 |
| 直接 loadData('PROCESS_TABLE') 导致格式依赖 | 进程表结构变更时调用方易出错 | 改为通过 ProcessManager 的公开 API 访问进程表，避免依赖内部序列化格式 |

---

## 三、ProcessManager 与 MemoryManager（进程与内存）

| 现象 | 可能原因 | 排查与解决 |
|------|----------|------------|
| 进程退出后仍能 loadData(pid, key) | freeMemory 未调用或 APPLICATION_SOP 未清理该 pid | 确认 ProcessManager 退出流程中调用了 MemoryManager.freeMemory(pid)，且 APPLICATION_SOP 已删除该 pid |
| 新进程复用 pid 后读到旧数据 | 释放时未清空分区或未从 APPLICATION_SOP 移除 | 确保 freeMemory 中既释放物理/逻辑分区，又删除 APPLICATION_SOP 中该 pid 的条目 |
| PROCESS_TABLE 与 APPLICATION_SOP 不一致 | 某处只更新了一方 | 创建时先写 PROCESS_TABLE 再 allocateMemory；退出时先更新 PROCESS_TABLE 再 freeMemory，顺序一致 |

---

## 四、事件与就绪

| 现象 | 可能原因 | 排查与解决 |
|------|----------|------------|
| waitLoaded 一直不 resolve | dependencyLoaded 未派发或路径与 dependencyMap 不一致 | 确认各模块脚本末尾调用了 publishSignal(正确路径)；DependencyConfig 监听到的 type 与 dependencyMap 键一致 |
| 主题/语言切换后 UI 未更新 | 未监听对应事件或未在 handler 中刷新 | 在 GUIManager、TaskbarManager 等中 addEventListener 对应事件，并在 handler 中更新 DOM/样式 |

---

## 五、本节小结

- 应用与内核边界问题：重点查 **pid、栈、状态、权限、apiName/args、recordKernelModuleCall**。
- 模块通信与协作问题：重点查 **POOL 注册/获取时机与名称、KernelMemory key 与单写方、进程退出顺序与 freeMemory/窗口/事件清理、事件派发与监听**。更细的调用链见 5.4。
