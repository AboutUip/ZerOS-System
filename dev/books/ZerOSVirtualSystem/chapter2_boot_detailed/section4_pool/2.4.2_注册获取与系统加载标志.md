# 2.4.2 注册、获取与系统加载标志

## 本节导读（阅读目标）

本节使读者能够：**① 完全理解 __ADD__、__GET__、__HAS__、__REMOVE__ 的每一行逻辑，包括 name 校验、枚举简写（type+name → realType）、系统加载标志的拒绝添加与永久删除；② 明确 __IS_SYSTEM_LOADING__ 的用途及与 BootLoader 的配合；③ 接手维护时能正确注册/获取 POOL 元素、排查“取到 undefined”或“拒绝添加标志位”，并理解为何“删除标志位后不可再添加”。** 下文给出**带行号与中文注释的完整源码**、**行为流程**与**接手维护要点**。源码文件：`kernel/core/signal/pool.js`。

## 一、__ADD__(type, name, elem) — 完整源码与注释（第 108–136 行）

```javascript
    /**
     * 添加或覆盖某个类别下的命名元素。
     * 若 name 为空将打印警告并忽略。
     * 特殊：系统加载标志位一旦被删除，永久拒绝添加。
     */
    __ADD__(type, name, elem) {
        if (typeof name === "undefined" || name === null || name === "") {
            KernelLogger.warn("POOL", "__ADD__: name 不能为空或空字符串", { type, name });
            return;
        }
        // 【枚举简写】若 type 为对象且 name 是该对象的属性名，则用 type[name] 作为真实类别
        // 例如 POOL.__ADD__(GroupEnum.POOL, "Dependency", obj) 且 GroupEnum.POOL === "KERNEL_GLOBAL_POOL"
        let realType = type;
        if (
            this.__isObject__(type) &&
            typeof name === "string" &&
            Object.prototype.hasOwnProperty.call(type, name)
        ) {
            realType = type[name];
        }
        const key = this.__normalizeKey__(realType);

        // 【系统加载标志保护】若尝试添加的是系统加载标志，且该标志已被永久删除，则拒绝
        if (name === this.__SYSTEM_LOADING_FLAG__ && this.__SYSTEM_LOADING_REMOVED__) {
            KernelLogger.warn("POOL", `拒绝添加系统加载标志位 ${name}：系统加载已完成，标志位已被永久删除（安全策略）`);
            return;
        }

        if (!this.__KEY_POOL__.has(key)) this.__UPDATE__(realType);
        const obj = this.__KEY_POOL__.get(key);
        obj[name] = elem;  // 覆盖同 name 的旧值
    },
```

**行为流程**：  
1. name 为空 → 警告并 return。  
2. 解析 realType（枚举简写时 realType = type[name]）。  
3. 若 name 为 __SYSTEM_LOADING_FLAG__ 且 __SYSTEM_LOADING_REMOVED__ 为 true → 警告并 return。  
4. 若类别不存在则 __UPDATE__(realType)，再 get 类别对象并 obj[name] = elem。

## 二、__GET__(type, name) — 完整源码与注释（第 147–165 行）

```javascript
    /**
     * 获取类别对象或类别下某个命名元素。
     * __GET__(type) => 类别对象（引用）或 { isInit: false }
     * __GET__(type, name) => 具体元素（可能为 undefined）
     */
    __GET__(type, name) {
        let realType = type;
        if (
            this.__isObject__(type) &&
            typeof name === "string" &&
            Object.prototype.hasOwnProperty.call(type, name)
        ) {
            realType = type[name];
        }
        const key = this.__normalizeKey__(realType);
        if (!this.__KEY_POOL__.has(key)) return { isInit: false };
        const obj = this.__KEY_POOL__.get(key);
        if (typeof name === "undefined") return obj;
        return obj[name];
    },
```

**行为流程**：  
1. 枚举简写时用 type[name] 得到 realType。  
2. 类别不存在 → 返回 { isInit: false }。  
3. 无 name → 返回类别对象（引用）。  
4. 有 name → 返回 obj[name]（未注册则为 undefined）。

**注意**：__GET__(type) 在类别不存在时返回 { isInit: false }，与“空类别对象”区分；__GET__(type, name) 在类别不存在时实际会从 { isInit: false } 上取 name，得到 undefined。

## 三、__HAS__(type, name) — 完整逻辑（第 174–191 行）

与 __GET__ 相同的 realType 解析；若类别不存在返回 false；若未传 name 返回 true（表示类别存在）；否则返回 Object.prototype.hasOwnProperty.call(obj, name)。

## 四、__REMOVE__(type, name) — 完整源码与注释（第 201–224 行）

```javascript
    /**
     * 删除类别或类别下的某个名称。
     * __REMOVE__(type) => 删除整个类别
     * __REMOVE__(type, name) => 删除该类别下的单项
     * 特殊：删除系统加载标志位时，标记永久删除，拒绝后续添加。
     */
    __REMOVE__(type, name) {
        let realType = type;
        if (
            this.__isObject__(type) &&
            typeof name === "string" &&
            Object.prototype.hasOwnProperty.call(type, name)
        ) {
            realType = type[name];
        }
        const key = this.__normalizeKey__(realType);
        if (!this.__KEY_POOL__.has(key)) return;
        if (typeof name === "undefined") {
            this.__KEY_POOL__.delete(key);
            return;
        }
        const obj = this.__KEY_POOL__.get(key);
        if (Object.prototype.hasOwnProperty.call(obj, name)) {
            if (name === this.__SYSTEM_LOADING_FLAG__) {
                this.__SYSTEM_LOADING_REMOVED__ = true;
                KernelLogger.info("POOL", `系统加载标志位已删除，系统加载完成。此后永久拒绝添加该标志位（安全策略）`);
            }
            delete obj[name];
        }
    },
```

**行为流程**：  
1. 解析 realType；类别不存在则 return。  
2. 未传 name → 删除整个类别（delete key）。  
3. 传了 name：若该 name 存在且为 __SYSTEM_LOADING_FLAG__，则置 __SYSTEM_LOADING_REMOVED__ = true，再 delete obj[name]。

**设计原因**：“系统加载完成”为不可逆状态；持久化/权限等若依赖“是否在加载中”，不允许通过再次添加标志位绕过。

## 五、__IS_SYSTEM_LOADING__() — 完整源码与注释（第 230–238 行）

```javascript
    __IS_SYSTEM_LOADING__() {
        if (this.__SYSTEM_LOADING_REMOVED__) return false;
        const flag = this.__GET__("KERNEL_GLOBAL_POOL", this.__SYSTEM_LOADING_FLAG__);
        return flag === true;
    },
```

**行为流程**：若已永久删除标志位则直接 false；否则查 KERNEL_GLOBAL_POOL 下名为 __SYSTEM_LOADING_FLAG__ 的项，仅当值为 true 时返回 true。  
与 BootLoader 的配合：引导开始时可在 KERNEL_GLOBAL_POOL 下 __ADD__(__SYSTEM_LOADING_FLAG__, true)；就绪后 __REMOVE__ 该 name，此后 __IS_SYSTEM_LOADING__() 恒为 false，且无法再添加该标志。

## 六、文件末尾 POOL 发布与 DependencyConfig（第 345–358 行）

```javascript
if (typeof DependencyConfig !== 'undefined') {
    DependencyConfig.publishSignal("../kernel/core/signal/pool.js");
} else {
    if (typeof document !== 'undefined' && document.body) {
        const publishWhenReady = () => {
            if (typeof DependencyConfig !== 'undefined') {
                DependencyConfig.publishSignal("../kernel/core/signal/pool.js");
            } else {
                setTimeout(publishWhenReady, 10);
            }
        };
        publishWhenReady();
    }
}
```

POOL 脚本加载后会发布自身路径信号，供 DependencyConfig 的依赖图使用；若 DependencyConfig 尚未就绪则轮询直到可 publishSignal，避免 BootLoader 的依赖顺序导致未发布。

## 七、接手维护要点

- **“取到 undefined”**：确认 __ADD__ 的 type/name 与 __GET__ 一致（含枚举简写）；确认在模块已执行并 __ADD__ 之后再 __GET__。  
- **“拒绝添加系统加载标志位”**：说明此前已 __REMOVE__ 过该标志位，属预期；若需在测试中重置，需 __CLEAR__() 全池（会重置 __SYSTEM_LOADING_REMOVED__）。  
- **新增注册项**：统一用字符串 type 或枚举 + name，避免 type 为未序列化对象导致键不稳定。
