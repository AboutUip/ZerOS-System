# 2.4.1 POOL 结构与类别管理

## 本节导读（阅读目标）

本节使读者能够：**① 完全理解 POOL 的单例形态与 __KEY_POOL__ 的数据结构，以及“类别（type）→ 命名元素（name → elem）”的映射关系；② 明确 __normalizeKey__、__extractEnumValues__ 的每一行作用及为何需要键规范化与枚举提取；③ 掌握 __UPDATE__ 与 __INIT__ 的完整行为流程，知道在何处会隐式创建类别；④ 接手维护时能正确新增类别、排查“取不到元素”或“类别未创建”问题。** 下文给出**带行号与中文注释的完整/关键源码**、**行为流程**与**接手维护要点**。源码文件：`kernel/core/signal/pool.js`。

## 一、POOL 的单例与内部结构（第 1–13 行）

```javascript
// 全局暂存区（对象池）
// 注意：初始化时不使用 KernelLogger，避免循环依赖
const POOL = {
    // 是否已执行过 __INIT__；清空时会被置为 false，用于判断“池是否已初始化”
    __IS_INITED__: false,
    // 【核心存储】Map<normalizedKey, 类别对象>
    // 键：经 __normalizeKey__(type) 得到的字符串；值：普通对象，其属性名为 name，属性值为 elem
    // 即逻辑上：__KEY_POOL__.get(normalizedType)[name] = elem
    __KEY_POOL__: new Map(),
    // 系统加载标志位的“名称”；添加在 KERNEL_GLOBAL_POOL 类别下，值为 true 表示系统正在加载
    __SYSTEM_LOADING_FLAG__: 'SYSTEM_LOADING',
    // 一旦该标志位被 __REMOVE__ 删除，置为 true，且永久拒绝再次 __ADD__ 该标志（安全策略）
    __SYSTEM_LOADING_REMOVED__: false,
```

**行为要点**：POOL 是单例对象，所有模块通过同一引用访问；__KEY_POOL__ 是唯一真实存储，其余属性为状态或常量。文件末尾有 `Object.freeze(POOL)`，防止外层方法被替换，但 Map 与类别对象内部仍可增删改。

## 二、__normalizeKey__(type) — 类别键规范化（第 21–36 行）

```javascript
    /**
     * 将任意 type 规范化为字符串键，保证同一逻辑类别在 Map 中只对应一个条目。
     * 支持：number/string/symbol/object/null/undefined。
     */
    __normalizeKey__(type) {
        if (typeof type === "symbol") return type.toString();
        if (typeof type === "undefined") return "undefined";
        if (type === null) return "null";
        if (typeof type === "object") {
            try {
                return JSON.stringify(type);
            } catch (e) {
                return String(type);  // 不可序列化时退回到 "[object Object]" 等
            }
        }
        return String(type);  // number/string 等
    },
```

**行为流程**：symbol → toString()；undefined/null/object 分别得到 "undefined"/"null"/JSON 或 String(type)；其余用 String(type)。这样不同引用但内容相同的对象（若 JSON 相同）会得到同一键，避免“同一逻辑类别因引用不同而重复条目”。

**为何需要**：Map 的键按引用比较；若直接用对象当键，每次传入新对象会得到新条目。规范化后，调用方可用字符串 "KERNEL_GLOBAL_POOL" 或枚举值，都能稳定对应同一键。

## 三、__isObject__ 与 __extractEnumValues__ — 枚举支持（第 42–76 行）

```javascript
    __isObject__(v) {
        return typeof v === "object" && v !== null;
    },

    /**
     * 从伪枚举对象中提取所有可作为类别键的原始值（number/string/symbol）
     * 支持一层或两层嵌套，例如 GroupEnum 或 GroupEnum.POOL。
     */
    __extractEnumValues__(obj) {
        const results = [];
        if (!this.__isObject__(obj)) return results;
        Object.keys(obj).forEach((k) => {
            const v = obj[k];
            const t = typeof v;
            if (t === "number" || t === "string" || t === "symbol") {
                results.push(v);
            } else if (this.__isObject__(v)) {
                // 二层：如 { POOL: { A: "A", B: "B" } }
                Object.keys(v).forEach((k2) => {
                    const v2 = v[k2];
                    const t2 = typeof v2;
                    if (t2 === "number" || t2 === "string" || t2 === "symbol") {
                        results.push(v2);
                    }
                });
            }
        });
        return results;
    },
```

**行为流程**：若 obj 非对象则返回 []；否则遍历 obj 的键，值为原始类型则 push，值为对象则再遍历其键值并 push 原始类型。这样 __UPDATE__(GroupEnum) 可一次为 GroupEnum 中所有枚举值（如 "KERNEL_GLOBAL_POOL"、"DOM"）创建类别。

**设计原因**：多处代码使用“枚举对象”统一管理类别名（如 GroupEnum.POOL），一次 __INIT__(GroupEnum) 或 __UPDATE__(GroupEnum) 即可创建多类，减少重复与拼写错误。

## 四、__UPDATE__(type) — 确保类别存在（第 82–98 行）

```javascript
    /**
     * 确保类别存在：若不存在则创建并标记 isInit。
     * 若 type 为伪枚举对象，则为其每个枚举值创建类别。
     */
    __UPDATE__(type) {
        if (this.__isObject__(type)) {
            const vals = this.__extractEnumValues__(type);
            vals.forEach((v) => {
                const k = this.__normalizeKey__(v);
                if (!this.__KEY_POOL__.has(k))
                    this.__KEY_POOL__.set(k, { isInit: true });
            });
            return;
        }
        const key = this.__normalizeKey__(type);
        if (!this.__KEY_POOL__.has(key)) {
            this.__KEY_POOL__.set(key, { isInit: true });
        }
    },
```

**行为流程**：  
1. 若 type 为对象：提取枚举值，对每个值规范化得到 k，若 __KEY_POOL__.has(k) 为 false 则 set(k, { isInit: true })。  
2. 否则：key = __normalizeKey__(type)，若不存在则 set(key, { isInit: true })。  
不覆盖已有条目，即已存在的类别对象不会被替换。

**何时被调用**：__INIT__ 中会对每个传入的 type 调用 __UPDATE__；__ADD__ 在发现类别不存在时会先调用 __UPDATE__(realType) 再写入。因此“首次按某 type 注册元素”会隐式创建该类别。

## 五、__INIT__(datas) — 批量初始化（第 296–334 行）

```javascript
    __INIT__(datas) {
        KernelLogger.info("POOL", "pool init start");
        if (typeof datas === "undefined" || datas === null) {
            datas = [];
        }
        if (!Array.isArray(datas)) {
            // 单个值或单个对象
            if (this.__isObject__(datas)) {
                const vals = this.__extractEnumValues__(datas);
                if (vals.length > 0) {
                    vals.forEach((v) => this.__UPDATE__(v));
                } else {
                    Object.keys(datas).forEach((k) => this.__UPDATE__(datas[k]));
                }
            } else {
                this.__UPDATE__(datas);
            }
        } else {
            datas.forEach((init_type) => {
                if (this.__isObject__(init_type)) {
                    const vals = this.__extractEnumValues__(init_type);
                    if (vals.length > 0)
                        vals.forEach((v) => this.__UPDATE__(v));
                    else
                        Object.keys(init_type).forEach((k) =>
                            this.__UPDATE__(init_type[k])
                        );
                } else {
                    this.__UPDATE__(init_type);
                }
            });
        }
        this.__IS_INITED__ = true;
        KernelLogger.info("POOL", "pool init complete");
    },
```

**行为流程**：  
1. datas 为空则当作 []。  
2. 若 datas 非数组：若为对象则按枚举或 keys 逐个 __UPDATE__；否则 __UPDATE__(datas)。  
3. 若 datas 为数组：对每项 init_type，对象则枚举或 keys 逐个 __UPDATE__，否则 __UPDATE__(init_type)。  
4. 最后 __IS_INITED__ = true。  
不清空已有类别，只“确保存在”；清空需显式 __CLEAR__()。

## 六、__GET_ALL__(type) 与 __CLEAR__(type)（第 244–291 行）

**__GET_ALL__(type)**：返回某类别的**浅拷贝**，避免外部直接修改池内引用。若 type 为枚举对象，会合并其所有枚举值对应类别的键值到 merged。  
**__CLEAR__()**：清空 __KEY_POOL__，__IS_INITED__ = false，__SYSTEM_LOADING_REMOVED__ = false（允许再次使用系统加载标志）。  
**__CLEAR__(type)**：仅删除该类别对应的键。

---

## 七、行为流程小结（类别从无到有）

1. BootLoader 或某处调用 `POOL.__INIT__("KERNEL_GLOBAL_POOL")` 或传入枚举 → __UPDATE__ 被调用 → __KEY_POOL__.set("KERNEL_GLOBAL_POOL", { isInit: true })。  
2. 某模块 `POOL.__ADD__("KERNEL_GLOBAL_POOL", "Dependency", dependencyConfig)` → 若 key 已存在则直接 get 后 obj["Dependency"] = dependencyConfig；若不存在则先 __UPDATE__ 再写入。  
3. 另一处 `POOL.__GET__("KERNEL_GLOBAL_POOL", "Dependency")` → 取到类别对象再取 name，得到 dependencyConfig。

---

## 八、接手维护要点

- **新增类别**：可显式 `POOL.__INIT__(["NEW_CATEGORY"])` 或 `POOL.__UPDATE__("NEW_CATEGORY")`，或在首次 __ADD__(type, name, elem) 时由 __ADD__ 内部 __UPDATE__ 创建。  
- **“取不到元素”**：检查 type/name 是否与 __ADD__ 时一致（含枚举简写时 realType 解析）；检查是否在 POOL 初始化与模块 publishSignal 之后才 __GET__。  
- **“类别未创建”**：确认 __INIT__ 或至少一次 __ADD__(type, ...) 已执行；若用枚举，确认 __extractEnumValues__ 能提到该值（原始类型才会被加入）。
