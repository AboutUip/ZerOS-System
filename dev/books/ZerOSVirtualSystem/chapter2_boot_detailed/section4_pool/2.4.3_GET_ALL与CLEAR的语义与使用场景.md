# 2.4.3 __GET_ALL__ 与 __CLEAR__ 的语义与使用场景

## 本节导读（阅读目标）

本节让读者**完完全全参透** POOL 的 **__GET_ALL__(type)** 与 **__CLEAR__(type)**：__GET_ALL__ 返回某类别的**浅拷贝**、对枚举对象的合并逻辑、以及为何需要“拷贝”而非直接返回引用；__CLEAR__ 对单类别与全池的清空、与 __IS_INITED__/__SYSTEM_LOADING_REMOVED__ 的重置关系。学完后能正确选用 __GET__/__GET_ALL__/__CLEAR__，并能判断在测试或重置场景下何时使用 __CLEAR__()。源码：`kernel/core/signal/pool.js`。

---

## 一、__GET_ALL__(type) 的完整语义（pool.js 约 244–272 行）

**作用**：返回某**类别**下所有“名称 → 元素”的**浅拷贝**对象，键为 name，值为 elem。若 type 为**伪枚举对象**（如 GroupEnum），则将该枚举对象中所有枚举值对应的类别**合并**到一个对象中返回。

**要点**：

- **浅拷贝**：避免调用方直接修改返回对象导致篡改 POOL 内部数据；调用方对拷贝对象的增删不影响 __KEY_POOL__。
- **枚举合并**：若传入 `__GET_ALL__(GroupEnum)` 且 GroupEnum 有 POOL、DOM 等字段，则 __extractEnumValues__ 得到各枚举值，对每个值取对应类别对象，将所有键值对合并到 merged，同一 name 在不同类别中若存在则后者覆盖前者（取决于 forEach 顺序）。
- **类别不存在**：若 type 为单值且 __KEY_POOL__.has(key) 为 false，返回 `{ isInit: false }`（与 __GET__(type) 一致）；若为枚举且无有效值，返回空对象或 { isInit: false }（见源码分支）。

**使用场景**：需要“只读遍历某类别下所有注册项”或“导出快照”时用 __GET_ALL__；需要“按 name 取单项”时用 __GET__(type, name)。

---

## 二、__CLEAR__(type) 的完整语义（约 279–291 行）

- **__CLEAR__()**（无参）：清空整个 __KEY_POOL__（Map.clear()），并将 __IS_INITED__ = false、**__SYSTEM_LOADING_REMOVED__ = false**。即全池重置后，系统加载标志的“永久拒绝再添加”状态被解除，便于测试或重新引导。
- **__CLEAR__(type)**：仅删除该 type 对应的键（__normalizeKey__(type) 后 delete），不影响其他类别，也不动 __IS_INITED__ 或 __SYSTEM_LOADING_REMOVED__。

**使用场景**：测试中需要“干净环境”时可 __CLEAR__()；仅需清空某类别（如某类别的临时缓存）时 __CLEAR__(type)。注意 __CLEAR__() 后若再次引导，需重新 __INIT__ 或依赖后续 __ADD__ 触发的 __UPDATE__。

---

## 三、本节小结与维护要点

- __GET_ALL__ 用于只读快照或遍历，避免外部篡改内部引用；__CLEAR__() 全量重置并重置系统加载标志状态。
- 修漏洞或做“重置后重跑引导”的测试时，注意 __CLEAR__() 会清空所有类别，包括 KERNEL_GLOBAL_POOL 中的 Dependency、GUIManager 等，需在测试脚本中重新初始化或重新加载页面。
