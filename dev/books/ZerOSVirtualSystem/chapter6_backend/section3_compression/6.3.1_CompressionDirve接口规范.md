# 6.3.1 CompressionDirve 接口规范

## 本节导读

本节使读者能够：**① 理解 CompressionDirve 的定位——作为后端压缩解压缩服务，为前端提供统一的压缩处理 API；② 掌握服务提供的核心接口——compress（压缩）、decompress（解压）、list（列出压缩包内容）；③ 理解接口的参数规范与返回值格式。** 源码位置：`system/service/CompressionDirve.php`。

---

## 一、服务概述

### 1.1 定位与职责

CompressionDirve 是 ZerOS 后端的压缩解压缩服务，负责：
- ZIP 文件的创建（压缩）
- ZIP 文件的提取（解压缩）
- ZIP 内部文件列表查询

### 1.2 访问地址

```
POST /system/service/CompressionDirve.php?action=compress
POST /system/service/CompressionDirve.php?action=decompress
POST /system/service/CompressionDirve.php?action=list
```

---

## 二、接口规范

### 2.1 压缩接口 (compress)

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| action | string | 是 | `compress` |
| sourcePaths | array | 是 | 要压缩的文件/目录路径列表 |
| targetPath | string | 是 | 目标 ZIP 文件路径 |
| basePath | string | 否 | 压缩时的基础路径 |

**请求示例**：

```json
{
    "action": "compress",
    "sourcePaths": ["D:/folder/file1.txt", "D:/folder/file2.txt"],
    "targetPath": "D:/archive.zip",
    "basePath": "D:/folder"
}
```

**响应格式**：

```json
{
    "success": true,
    "message": "压缩成功",
    "timestamp": "2026-03-16 15:30:00",
    "data": {
        "path": "D:/archive.zip",
        "size": 1024,
        "fileCount": 2
    }
}
```

### 2.2 解压接口 (decompress)

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| action | string | 是 | `decompress` |
| archivePath | string | 是 | 要解压的 ZIP 文件路径 |
| targetPath | string | 是 | 解压目标目录 |
| overwrite | boolean | 否 | 是否覆盖已存在文件，默认 false |

**请求示例**：

```json
{
    "action": "decompress",
    "archivePath": "D:/archive.zip",
    "targetPath": "D:/output",
    "overwrite": true
}
```

**响应格式**：

```json
{
    "success": true,
    "message": "解压成功",
    "data": {
        "extractedPath": "D:/output",
        "fileCount": 10,
        "totalSize": 51200
    }
}
```

### 2.3 列表接口 (list)

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| action | string | 是 | `list` |
| archivePath | string | 是 | ZIP 文件路径 |

**请求示例**：

```json
{
    "action": "list",
    "archivePath": "D:/archive.zip"
}
```

**响应格式**：

```json
{
    "success": true,
    "message": "查询成功",
    "data": {
        "path": "D:/archive.zip",
        "files": [
            {
                "name": "folder/file1.txt",
                "size": 1024,
                "compressedSize": 512,
                "modified": 1701234567
            },
            {
                "name": "folder/file2.txt",
                "size": 2048,
                "compressedSize": 1024,
                "modified": 1701234567
            }
        ],
        "totalSize": 3072,
        "compressedSize": 1536
    }
}
```

## 三、与前端内核的协作

### 3.1 NetworkManager 封装

```javascript
// kernel/drive/compressionDrive.js

async compress(sourcePaths, targetPath, basePath) {
    return await NetworkManager.request('CompressionDirve', {
        action: 'compress',
        sourcePaths,
        targetPath,
        basePath
    });
}

async decompress(archivePath, targetPath, overwrite = false) {
    return await NetworkManager.request('CompressionDirve', {
        action: 'decompress',
        archivePath,
        targetPath,
        overwrite
    });
}

async list(archivePath) {
    return await NetworkManager.request('CompressionDirve', {
        action: 'list',
        archivePath
    });
}
```

---

## 本节小结

本节讲解了 CompressionDirve 接口规范：

1. **compress**：将多个文件/目录压缩为 ZIP
2. **decompress**：将 ZIP 文件解压到指定目录
3. **list**：列出 ZIP 内部文件及信息
