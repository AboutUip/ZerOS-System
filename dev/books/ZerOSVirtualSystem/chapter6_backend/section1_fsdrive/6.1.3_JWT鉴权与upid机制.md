# 6.1.3 JWT 鉴权与 upid 机制

## 本节导读

本节使读者能够：**① 理解 JWT Token 的生成、存储、与校验流程；② 掌握 upid（程序唯一标识）的分配与管理机制；③ 理解权限校验的完整链路——Token → upid → 权限枚举 → 允许/拒绝。** 源码位置：`system/service/randomSecurity.php`、`system/service/jwtVerify.php`、`system/service/programPermissions.php`。

## 一、JWT Token 概述

### 1.1 什么是 JWT

JWT（JSON Web Token）是一种开放标准（RFC 7519），用于在各方之间安全地传输 JSON 格式的信息。ZerOS 使用 JWT 作为用户登录的状态凭证：

```
Header.Payload.Signature
```

- **Header**：声明算法类型（如 HS256）
- **Payload**：存放实际数据（用户信息、过期时间等）
- **Signature**：对 Header + Payload 的签名，防止数据篡改

### 1.2 ZerOS 中的 JWT 用途

ZerOS 使用两种 JWT Token：

| Token 类型 | 用途 | 存储位置 | 有效期 |
|-----------|------|---------|--------|
| SystemToken | 系统级操作 | LStorage (system) | 可配置 |
| UserToken | 用户操作 | LStorage (user) | 登录会话 |

## 二、Token 的生成 (randomSecurity)

### 2.1 randomSecurity 服务

`randomSecurity.php` 负责签发 JWT Token：

```php
<?php
// system/service/randomSecurity.php

header('Content-Type: application/json; charset=utf-8');
header('Access-Control-Allow-Origin: *');

require_once __DIR__ . '/jwtVerify.php';

$action = $_GET['action'] ?? '';

// 签发 Token
if ($action === 'issue') {
    $username = $_POST['username'] ?? '';
    $password = $_POST['password'] ?? '';
    $tokenType = $_POST['tokenType'] ?? 'UserToken'; // 或 SystemToken
    
    // 1. 验证用户名密码
    $userData = verifyCredentials($username, $password);
    if (!$userData) {
        sendResponse(false, '用户名或密码错误', null, 401);
    }
    
    // 2. 生成 JWT
    $token = generateJWT([
        'username' => $username,
        'userId' => $userData['id'],
        'type' => $tokenType,
        'permissions' => $userData['permissions']
    ]);
    
    // 3. 返回 Token
    sendResponse(true, '签发成功', [
        'token' => $token,
        'tokenType' => $tokenType,
        'username' => $username
    ]);
}

// 清除 Token
if ($action === 'clear') {
    sendResponse(true, '清除成功', null);
}
```

### 2.2 JWT 生成实现

```php
function generateJWT($payload) {
    $secret = getJWTSecret(); // 从配置获取签名密钥
    
    // Header
    $header = [
        'typ' => 'JWT',
        'alg' => 'HS256'
    ];
    
    // Payload
    $payload['iat'] = time(); // 签发时间
    $payload['exp'] = time() + getTokenExpireSeconds(); // 过期时间
    
    // Base64 编码
    $headerEncoded = base64UrlEncode(json_encode($header));
    $payloadEncoded = base64UrlEncode(json_encode($payload));
    
    // 签名
    $signature = hash_hmac('sha256', 
        $headerEncoded . '.' . $payloadEncoded, 
        $secret
    );
    $signatureEncoded = base64UrlEncode($signature);
    
    return $headerEncoded . '.' . $payloadEncoded . '.' . $signatureEncoded;
}

function base64UrlEncode($data) {
    return rtrim(strtr(base64_encode($data), '+/', '-_'), '=');
}
```

## 三、Token 的校验 (jwtVerify)

### 3.1 jwtVerify 中间件

每个后端服务引入 `jwtVerify.php` 来校验请求中的 Token：

```php
<?php
// system/service/jwtVerify.php

function requireJWTVerify($serviceName) {
    // 允许跳过验证的路径
    $whitelist = ['/randomSecurity', '/install-service'];
    foreach ($whitelist as $path) {
        if (strpos($_SERVER['REQUEST_URI'], $path) !== false) {
            return; // 白名单路径跳过验证
        }
    }
    
    // 获取 Token
    $token = $_SERVER['HTTP_X_JWT'] ?? $_GET['jwt'] ?? '';
    
    if (empty($token)) {
        sendResponse(false, '缺少认证 Token', null, 401);
    }
    
    // 校验 Token
    $payload = verifyJWT($token);
    if (!$payload) {
        sendResponse(false, '无效的 Token', null, 401);
    }
    
    // 校验服务权限（可选）
    if (!checkServicePermission($payload, $serviceName)) {
        sendResponse(false, '无权限访问该服务', null, 403);
    }
    
    // 将用户信息存入全局变量，供后续使用
    $GLOBALS['jwt_payload'] = $payload;
}

function verifyJWT($token) {
    $parts = explode('.', $token);
    if (count($parts) !== 3) {
        return false;
    }
    
    list($headerEncoded, $payloadEncoded, $signatureEncoded) = $parts;
    
    // 验证签名
    $secret = getJWTSecret();
    $expectedSignature = base64UrlEncode(hash_hmac('sha256', 
        $headerEncoded . '.' . $payloadEncoded, 
        $secret
    ));
    
    if (!hash_equals($expectedSignature, $signatureEncoded)) {
        return false;
    }
    
    // 解析 Payload
    $payload = json_decode(base64UrlDecode($payloadEncoded), true);
    
    // 检查过期时间
    if (isset($payload['exp']) && $payload['exp'] < time()) {
        return false;
    }
    
    return $payload;
}
```

## 四、upid 机制

### 4.1 什么是 upid

**upid（Program Unique Identifier）** 是 ZerOS 中每个程序的唯一标识符，用于关联程序与其拥有的权限。

- **格式**：`{programName}_{timestamp}_{random}`
- **示例**：`filemanager_1701234567_a1b2c3`

### 4.2 upid 的分配流程

```php
<?php
// system/service/programPermissions.php

function assignUpid($programName, $permissions) {
    // 1. 生成唯一 ID
    $timestamp = time();
    $random = substr(md5(uniqid(rand(), true)), 0, 6);
    $upid = $programName . '_' . $timestamp . '_' . $random;
    
    // 2. 存储程序权限映射
    $permissionsFile = DISK_D_PATH . '/LocalSData.json';
    $sdata = json_decode(file_get_contents($permissionsFile), true);
    
    if (!isset($sdata['permissionControl']['programPermissions'])) {
        $sdata['permissionControl']['programPermissions'] = [];
    }
    
    $sdata['permissionControl']['programPermissions'][$upid] = [
        'programName' => $programName,
        'permissions' => $permissions,
        'assignedAt' => $timestamp
    ];
    
    file_put_contents($permissionsFile, json_encode($sdata, JSON_PRETTY_PRINT));
    
    return $upid;
}
```

### 4.3 权限校验流程

```
请求到达 FSDirve
      │
      ▼
jwtVerify 校验 Token
      │
      ▼
获取 payload (包含 username, userId, type)
      │
      ▼
根据 username 查询用户权限
      │
      ▼
获取该程序对应的 upid 及其权限
      │
      ▼
检查操作所需的权限是否在 upid 权限列表中
      │
      ▼
允许 / 拒绝
```

```php
function checkPermission($upid, $requiredPermission) {
    // 1. 获取程序权限
    $permissions = getProgramPermissions($upid);
    
    if (!$permissions) {
        return false;
    }
    
    // 2. 检查是否有所需权限
    if (in_array($requiredPermission, $permissions)) {
        return true;
    }
    
    // 3. 检查是否为管理员
    if (isAdmin($upid)) {
        return true; // 管理员拥有所有权限
    }
    
    return false;
}
```

## 五、权限层级

### 5.1 权限等级

ZerOS 的权限分为三个等级：

| 等级 | 名称 | 说明 | 示例 |
|------|------|------|------|
| 0 | NORMAL | 普通权限，自动授予 | KERNEL_DISK_READ |
| 1 | SPECIAL | 特殊权限，需用户确认 | CAMERA_ACCESS |
| 2 | DANGEROUS | 危险权限，仅管理员可授权 | KERNEL_DISK_WRITE |

### 5.2 权限检查示例

```php
// 检查是否可写入系统存储
function canWriteSystemStorage($upid, $key) {
    $permissions = getProgramPermissions($upid);
    
    // 敏感键需要特殊权限
    $sensitiveKeys = ['userControl.', 'permissionControl.'];
    foreach ($sensitiveKeys as $prefix) {
        if (strpos($key, $prefix) === 0) {
            return hasDangerousPermission($upid, 'SYSTEM_STORAGE_WRITE_' . strtoupper($prefix));
        }
    }
    
    // 普通键只需要基础权限
    return in_array('SYSTEM_STORAGE_WRITE', $permissions);
}
```

## 六、敏感文件写入限制

### 6.1 背景

CVS-ZEROS-008 和 CVS-ZEROS-012 漏洞揭示了 FSDirve 对敏感文件的写入缺乏限制。修复后：

```php
function checkSensitiveFileWritePermission($upid, $path) {
    // 敏感文件列表
    $sensitiveFiles = [
        'D:/LocalSData.json',
        'D:/LocalCache.json',
        'D:/DiskData.json'
    ];
    
    // 检查是否为敏感文件
    $normalizedPath = str_replace('\\', '/', $path);
    foreach ($sensitiveFiles as $sensitive) {
        if ($normalizedPath === $sensitive) {
            // 敏感文件只能由 SystemToken 写入
            $payload = $GLOBALS['jwt_payload'] ?? null;
            return $payload && $payload['type'] === 'SystemToken';
        }
    }
    
    return true; // 非敏感文件正常校验
}
```

## 本节小结

本节详细讲解了 JWT 鉴权与 upid 机制：

1. **JWT Token**：Header.Payload.Signature 结构，用于状态保持
2. **randomSecurity**：签发 Token，验证用户名密码
3. **jwtVerify**：中间件形式校验 Token 有效性
4. **upid**：程序唯一标识符，关联程序与权限
5. **权限层级**：NORMAL → SPECIAL → DANGEROUS 三级
6. **敏感文件限制**：SystemToken 才能写入关键配置文件
