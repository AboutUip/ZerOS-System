# 7.1.1 系统驱动概述与加载机制

## 本节导读

本节使读者能够：**① 理解 ZerOS 中"驱动"的概念——与操作系统中的驱动不同，ZerOS 驱动是内核功能扩展模块；② 掌握驱动的分类——系统驱动（内核层）和应用驱动（应用层）；③ 理解驱动的加载机制——BootLoader 按依赖顺序加载。** 源码位置：`bootloader/starter.js`、各 `kernel/drive/*.js`。

---

## 一、驱动概念

### 1.1 什么是驱动

在 ZerOS 中，"驱动（Drive）"是内核功能扩展模块的统称。与传统操作系统（如 Windows、Linux）的硬件驱动不同，ZerOS 驱动是纯软件模块，用于提供特定功能：

- **CacheDrive**：缓存管理
- **CryptDrive**：加密解密
- **LStorage**：本地存储
- **NetworkManager**：网络请求

### 1.2 驱动的分类

| 分类 | 位置 | 加载时机 | 示例 |
|------|------|---------|------|
| 内核驱动 | kernel/drive/ | 引导阶段 | CacheDrive, CryptDrive |
| 系统驱动 | system/expansion/ | 引导阶段 | LanguagesExpansion |
| 应用驱动 | application/*/ | 程序运行时 | 应用自定义 |

## 二、驱动加载机制

### 2.1 MODULE_DEPENDENCIES 配置

驱动通过 `starter.js` 的 `MODULE_DEPENDENCIES` 配置加载：

```javascript
// bootloader/starter.js

const MODULE_DEPENDENCIES = {
    // 基础类型池
    'kernel/enumManager': [],
    'kernel/logLevel': ['kernel/enumManager'],
    'kernel/addressType': ['kernel/enumManager'],
    
    // 驱动层
    'kernel/drive/logger': ['kernel/logLevel'],
    'kernel/drive/cacheDrive': ['kernel/enumManager', 'kernel/drive/logger', 'kernel/filesystem/init'],
    'kernel/drive/cryptDrive': ['kernel/enumManager', 'kernel/drive/logger'],
    'kernel/drive/LStorage': ['kernel/drive/logger', 'kernel/drive/cacheDrive'],
    'kernel/drive/networkManager': ['kernel/drive/logger', 'kernel/drive/LStorage'],
    
    // ...
};
```

### 2.2 加载流程

```
BootLoader 启动
      │
      ▼
解析 MODULE_DEPENDENCIES
      │
      ▼
构建依赖图
      │
      ▼
拓扑排序确定加载顺序
      │
      ▼
按顺序加载驱动模块
      │
      ▼
执行模块初始化
      │
      ▼
驱动就绪
```

## 三、驱动注册机制

### 3.1 全局注册

驱动加载后注册到 POOL 和 window：

```javascript
// kernel/drive/cacheDrive.js

class CacheDrive {
    static async init() {
        // 初始化逻辑
    }
}

// 注册到 POOL
POOL.__SET__("KERNEL_GLOBAL_POOL", "CacheDrive", CacheDrive);

// 注册到 window
window.CacheDrive = CacheDrive;
```

### 3.2 获取驱动实例

```javascript
// 从 POOL 获取
const CacheDrive = POOL.__GET__("KERNEL_GLOBAL_POOL", "CacheDrive");

// 从 window 获取
const CacheDrive = window.CacheDrive;
```

## 四、驱动初始化

### 4.1 异步初始化

驱动通常需要异步初始化（如等待文件系统就绪）：

```javascript
class CacheDrive {
    static _ready = null;
    
    static async init() {
        // 异步初始化
        await this._loadCacheMetadata();
        
        // 设置就绪状态
        this._ready = Promise.resolve();
    }
    
    static async waitReady() {
        if (this._ready) {
            await this._ready;
        }
    }
}
```

### 4.2 引导阶段的等待

```javascript
// bootloader/starter.js

async function start_init() {
    // 等待文件系统就绪
    await Filesystem.init();
    
    // 等待驱动初始化
    await CacheDrive.waitReady();
    await CryptDrive.waitReady();
    await LStorage.waitReady();
    
    // 继续启动流程
    // ...
}
```

## 本节小结

本节讲解了 ZerOS 系统驱动的概述与加载机制：

1. **驱动概念**：内核功能扩展模块，不同于硬件驱动
2. **驱动分类**：内核驱动、系统驱动、应用驱动
3. **加载机制**：通过 MODULE_DEPENDENCIES 配置，拓扑排序确定顺序
4. **注册机制**：注册到 POOL 和 window，供全局访问
