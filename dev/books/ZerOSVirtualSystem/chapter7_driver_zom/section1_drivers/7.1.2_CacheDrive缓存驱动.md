# 7.1.2 CacheDrive 缓存驱动

## 本节导读

本节使读者能够：**① 理解 CacheDrive 的职责——统一管理内核、系统和应用程序的缓存；② 掌握缓存的存储结构——元数据文件和实际缓存文件分离；③ 理解 TTL（生存时间）机制和进程级缓存隔离的实现。** 源码位置：`kernel/drive/cacheDrive.js`。

---

## 一、缓存驱动概述

### 1.1 职责

CacheDrive 是 ZerOS 的统一缓存管理模块，提供：
- **系统级缓存**：所有程序共享
- **程序级缓存**：按 PID 隔离
- **TTL 支持**：缓存过期机制
- **文件缓存**：大对象可持久化到磁盘

### 1.2 存储位置

```
D:/cache/
├── sys_<key>.cache        # 系统缓存
├── prog_<programName>_<key>.cache  # 程序缓存
└── LocalCache.json        # 缓存元数据
```

## 二、核心 API

### 2.1 缓存操作

| 方法 | 说明 |
|------|------|
| `set(key, value, options)` | 设置缓存 |
| `get(key, defaultValue, options)` | 获取缓存 |
| `has(key, options)` | 检查缓存是否存在 |
| `delete(key, options)` | 删除缓存 |
| `clear(options)` | 清除缓存 |
| `getStats(options)` | 获取缓存统计 |

## 三、实现要点

### 3.1 进程级隔离

```javascript
static async set(key, value, options = {}) {
    const pid = options.pid || ProcessManager.getCurrentPid();
    const programName = await ProcessManager.getProcessProgramName(pid);
    
    // 程序缓存带程序名前缀
    const cacheKey = programName 
        ? `prog_${programName}_${key}` 
        : `sys_${key}`;
    
    // ... 存储逻辑
}
```

### 3.2 TTL 过期

```javascript
static async get(key, options = {}) {
    const metadata = await this._getMetadata(cacheKey);
    
    // 检查是否过期
    if (metadata.ttl > 0 && Date.now() > metadata.expireAt) {
        await this.delete(key, options);
        return options.defaultValue || null;
    }
    
    return metadata.value;
}
```
