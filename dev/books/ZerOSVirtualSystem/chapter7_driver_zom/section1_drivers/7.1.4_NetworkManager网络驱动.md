# 7.1.4 NetworkManager 网络驱动

## 本节导读

本节使读者能够：**① 理解 NetworkManager 的职责——统一管理所有网络请求，包括后端服务调用和外部 API 请求；② 掌握请求拦截机制——自动注入 JWT Token；③ 理解后端服务路由——如何将请求分发到不同的后端服务。** 源码位置：`kernel/drive/networkManager.js`。

---

## 一、网络驱动概述

### 1.1 职责

NetworkManager 是 ZerOS 的统一网络请求管理模块，提供：
- **后端服务调用**：统一调用 FSDirve、CompressionDirve 等后端服务
- **JWT Token 自动注入**：在请求头中自动添加认证信息
- **请求拦截**：可拦截 fetch/XHR 实现全局处理
- **错误处理**：统一的错误处理和重试机制

## 三、实现要点

### 3.1 JWT Token 自动注入

```javascript
async request(serviceName, data) {
    // 获取 JWT Token
    const token = await LStorage.getSystemStorage('jwtToken');
    
    // 构建请求
    const url = this.getServiceUrl(serviceName);
    const response = await fetch(url, {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json',
            'X-JWT': token || ''  // 自动注入
        },
        body: JSON.stringify(data)
    });
    
    // 处理响应
    const result = await response.json();
    
    if (!result.success) {
        throw new Error(result.message);
    }
    
    return result.data;
}
```

### 3.2 后端服务路由

```javascript
getServiceUrl(serviceName) {
    // 从配置或环境变量获取后端地址
    const backendUrl = SystemInformation.getBackendUrl();
    
    // 服务路径映射
    const servicePaths = {
        'FSDirve': '/system/service/FSDirve.php',
        'CompressionDirve': '/system/service/CompressionDirve.php',
        'DISKMANAGER': '/system/service/DISKMANAGER.php',
        // ...
    };
    
    return backendUrl + (servicePaths[serviceName] || '/system/service/' + serviceName + '.php');
}
```
