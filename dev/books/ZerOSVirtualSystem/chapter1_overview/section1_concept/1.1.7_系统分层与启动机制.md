# 1.1.7 系统分层与启动机制

## 本节导读

本节将作为1.1节的总结与过渡，帮助读者建立对 ZerOS 系统启动流程的整体认知。在理解内核的基本概念后，我们需要知道这些组件是如何协同工作、共同构成一个完整系统的。本节将从最基础的"引导"概念出发，逐步展开 ZerOS 的三层架构。

---

## 1.1.7.1 什么是引导

### 引导的定义

引导（Boot），是指计算机从断电状态到操作系统可用的完整过程。这个过程包括硬件初始化、系统自检、操作系统加载等步骤。在传统计算机中，引导过程由 BIOS/UEFI 固件和 BootLoader 共同完成。

引导的本质是"从无到有"的过程：计算机通电时，内存是空的，没有任何程序运行。引导过程就是要在这个空白状态下，建立起软件运行的基础环境。

### 引导的必要性

计算机需要引导的原因在于：

硬件初始化：处理器、内存、存储设备等需要正确初始化才能工作
程序加载：操作系统内核存储在磁盘中，需要被加载到内存才能执行
环境建立：需要建立内存管理、进程管理等基础数据结构

---

## 1.1.7.2 BootLoader 的职责

### BootLoader 的定义

BootLoader（引导加载器）是引导过程中负责加载操作系统的程序。它位于硬件与操作系统之间，承上启下。

### BootLoader 的核心任务

 BootLoader 的核心任务包括：

硬件探测：识别可用的存储设备、内存大小等
环境检测：检查硬件状态，确保满足系统运行条件
系统加载：将操作系统内核从存储设备加载到内存
参数传递：将启动参数传递给操作系统内核

### ZerOS 的 BootLoader

ZerOS 的 BootLoader 位于 bootloader/starter.js，它不处理传统硬件初始化（由浏览器完成），而专注于：

模块依赖管理：解析模块间的依赖关系
模块加载：按顺序加载 JavaScript 模块
环境初始化：建立 POOL 对象池等基础设施

---

## 1.1.7.3 Kernel 内核层

### Kernel 的定义

Kernel（内核）是操作系统的核心，负责管理系统最核心的资源。在 ZerOS 中，Kernel 层包括：

- 进程管理：ProcessManager
- 内存管理：MemoryManager
- 文件系统：Disk、NodeTree
- 安全控制：PermissionManager、UserControl

### Kernel 的核心职责

Kernel 的核心职责可以概括为"管理"与"抽象"：

资源管理：有效管理系统中的各种资源（CPU、内存、存储）
抽象提供：为上层软件提供与底层细节无关的编程接口

### ZerOS 的 Kernel 层

ZerOS 的 Kernel 层运行在浏览器环境中，通过 JavaScript 实现完整的资源管理抽象。它包括以下核心模块：

进程管理器：负责创建、调度、终止进程
内存管理器：负责内存的分配、回收、隔离
文件管理器：负责虚拟文件系统的组织与操作
权限管理器：负责安全检查与访问控制

---

## 1.1.7.4 System 系统层

### System 的定义

System（系统）层是用户直接感知的世界。它包括用户界面、系统服务、应用程序等组件。在 ZerOS 中，System 层负责将 Kernel 层的能力转化为用户可感知、可操作的形式。

### System核心组件 的

ZerOS 的 System 层包括：

 GUI 管理器（GUIManager）：负责窗口的创建、移动、关闭等操作
 事件管理器（EventManager）：负责用户交互的捕获与分发
 通知管理器（NotificationManager）：负责系统通知的显示
 任务栏管理器（TaskbarManager）：负责任务栏与开始菜单
 桌面管理器（DesktopManager）：负责桌面图标的组织

### System 与 Kernel 的关系

System 层依赖 Kernel 层提供的服务，同时为用户提供操作界面。这种分层设计使得：

职责分离：Kernel 专注资源管理，System 专注用户体验
模块化：各层可以独立演进，互不影响
可扩展性：可以在不修改 Kernel 的情况下扩展 System 功能

---

## 1.1.7.5 ZerOS 的完整启动流程

### 三层协作

ZerOS 的启动过程是三层协作的过程：

```
BootLoader → Kernel → System
    │          │       │
    ▼          ▼       ▼
  模块加载   资源管理   用户界面
  依赖解析   进程调度   事件处理
  环境初始化 内存分配   图形渲染
```

### 启动顺序

ZerOS 的启动顺序如下：

1. BootLoader 阶段：加载 starter.js，初始化依赖配置
2. Kernel 阶段：加载进程管理、内存管理、文件系统等核心模块
3. System 阶段：加载 GUI 管理、事件处理、通知系统等界面组件
4. 登录界面：显示锁屏，等待用户认证
5. 桌面环境：用户登录后显示桌面

### 模块依赖关系

 ZerOS 的模块加载采用拓扑排序，确保依赖的模块先被加载：

 Layer 1: SystemInformation, NetworkManager
 Layer 2-3: 类型池（FileType, LogLevel）
 Layer 4: 文件系统（disk, nodeTree, fileFramework）
 Layer 5: 内存管理（heap, shed, memoryManager）
 Layer 6: 进程管理（processManager, eventManager）
 Layer 7: GUI（guiManager, taskbar, desktop）
