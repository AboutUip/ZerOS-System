# 1.12.1 启动流程概览

## 本节导读

本节将介绍 ZerOS 启动流程的整体架构，帮助读者把前面各节所学的模块串联成一条完整的启动链路。理解各阶段在时间上的先后关系，有助于在调试和扩展时快速定位问题。

**本章自闭合说明**：1.12.3 节提供完整的**系统启动流程图**（Mermaid 图 1-1）及逐段解读，与本节四阶段一一对应；读者仅凭第一章即可掌握从 HTML 加载到系统就绪的完整过程。

## 启动阶段

ZerOS 的启动可以划分为四个主要阶段。每个阶段都有明确的目标和产出，前一阶段的产出是后一阶段的前提。

### HTML 加载阶段

页面加载时，浏览器会解析 HTML 并依次加载其中引用的脚本。在这一阶段，ZerOS 会优先加载**核心基础模块**的脚本文件，包括：

- **KernelLogger**：日志系统必须最先就绪，以便后续所有模块都能记录自己的初始化过程。
- **DependencyConfig**：依赖配置定义了“谁依赖谁”，为后续的加载顺序提供依据。
- **POOL（对象池）**：为各模块提供统一的全局共享存储，供依赖配置、加载器等使用。

这一阶段不执行复杂的业务逻辑，主要是把必要的代码和数据结构载入内存，为 BootLoader 的正式运行做好准备。

### BootLoader 初始化阶段

在脚本加载完成后，BootLoader 开始执行。这一阶段主要完成两件事：

- **初始化依赖配置**：根据各模块声明的依赖关系，构建依赖图并计算加载顺序（拓扑排序）。同时建立“等待依赖就绪”的机制（如 Promise、信号量等），以便模块可以声明“在谁之后加载”。
- **初始化对象池**：创建全局对象池实例，并可能注册一些在引导早期就需要共享的对象（如配置、环境信息等）。

此时尚未加载进程管理、文件系统等内核模块，系统仍处于“引导层”的范畴。

### 模块加载阶段

BootLoader 调用**模块加载器（Starter）**，按依赖顺序依次加载并初始化各模块。典型顺序为：

1. **内核层**：进程管理（ProcessManager）、内存管理（MemoryManager）、文件系统（Disk）等。
2. **系统层**：安全控制（PermissionManager）、GUI 窗口管理（GUIManager）、事件系统（EventManager）等。

每个模块在初始化时可能会向对象池注册自己的服务或数据，并可能依赖对象池中已由其他模块注册的内容。依赖配置和对象池共同保证了“被依赖者先于依赖者”的顺序，避免未初始化就被访问。

### 系统就绪阶段

当所有声明过的模块都加载并初始化完成后，启动流程进入收尾阶段：

- 各模块的“就绪”状态被汇总，BootLoader 或启动入口可以得知“系统已就绪”。
- GUI 层完成初始化后，可显示锁屏或主界面，等待用户登录与操作。
- 事件系统开始接收用户输入和系统事件，整个系统由“启动”转为“运行”。

此时 ZerOS 已完成从“空白页面”到“可用虚拟操作系统”的完整引导。

## 本节小结

本节将 ZerOS 启动流程概括为四个阶段：HTML 加载（核心脚本与基础模块就绪）→ BootLoader 初始化（依赖配置与对象池）→ 模块加载（按依赖顺序加载内核层与系统层）→ 系统就绪（界面呈现、等待用户）。理解这一时间线，有助于在阅读流程图和排查启动问题时建立清晰的时间顺序感。
