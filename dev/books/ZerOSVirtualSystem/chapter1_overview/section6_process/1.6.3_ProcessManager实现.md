# 1.6.3 ProcessManager 实现

## 本节导读

本节将介绍 ZerOS 中进程管理（ProcessManager）的实现要点。ProcessManager 在启动流程中负责提供“进程”抽象及程序启动、终止、调度等能力；详细实现见第 3 章，本节仅建立概述级认识。

---

## ProcessManager 在启动中的角色

### 功能概览

ProcessManager 在依赖图中依赖内存管理（MemoryManager）等模块，加载后通常向 **POOL** 注册自身实例，供系统层（如 GUIManager、应用启动逻辑）获取。其提供的核心能力包括：

- **程序启动与终止**：根据可执行对象（如应用配置、脚本路径）创建进程实例、分配 PID，并在退出或被杀时回收资源。
- **进程状态与调度**：维护进程的创建、就绪、运行、阻塞、终止等状态，并在 ZerOS 的协作式或事件驱动模型中参与调度（如将 CPU 时间或执行权交给当前前台进程）。
- **进程隔离与权限**：与 PermissionManager 等配合，在启动程序前做权限检查，并在进程生命周期内提供一定的隔离（如按进程限制可访问资源）。

### 与启动流程的关系

在 1.12 的启动流程图中，ProcessManager 位于内核层，在内存管理之后、EventManager 与 GUIManager 之前加载。系统层模块依赖它来启动应用、管理窗口与进程的对应关系，因此其就绪是“桌面与应用”可用的前提之一。

## 本节小结

本节概述了 ProcessManager 的职责：在引导流程中提供进程抽象、程序启动/终止、状态与调度，并向 POOL 注册供上层使用。具体数据结构与 API 见第 3 章。
