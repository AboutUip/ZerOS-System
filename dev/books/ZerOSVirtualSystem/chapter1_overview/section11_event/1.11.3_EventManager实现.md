# 1.11.3 EventManager 实现

## 本节导读

本节将介绍 ZerOS 中事件系统（EventManager）的实现要点。EventManager 负责事件的发布、订阅与派发，实现模块间的解耦通信；详细实现见第 4 章，本节仅建立概述级认识。

---

## EventManager 在启动中的角色

### 功能概览

EventManager 在依赖图中通常依赖 ProcessManager，并在许多系统层模块（GUIManager、任务栏、锁屏等）之前加载，以便这些模块在初始化时就能订阅事件。其提供的核心能力包括：

- **发布-订阅**：模块通过“事件类型 + 负载”发布事件，其他模块事先订阅该类型并注册回调；EventManager 在发布时遍历回调并调用，对应 1.11.2 的机制。
- **与 GUI、锁屏的配合**：用户点击、键盘输入、窗口关闭等先由 DOM 或 GUIManager 转为内部事件，再经 EventManager 派发给订阅者（如应用、任务栏、锁屏），实现“谁关心谁订阅”的松耦合。
- **系统就绪后的主循环**：启动完成后，系统进入“事件驱动”模式：EventManager 持续接收并派发事件，各模块通过订阅参与响应，整个系统由“启动”转为“运行”。

### 与启动流程的关系

在启动流程图中，EventManager 位于系统层，紧接 ProcessManager 之后、GUIManager 之前；锁屏与桌面依赖它来响应用户操作。阶段四“事件循环”即由 EventManager 支撑，因此其就绪是系统从启动过渡到可交互的前提。

---

## 本节小结

本节概述了 EventManager 的职责：在引导流程中提供发布-订阅与事件派发，与 GUIManager、锁屏等配合实现用户交互，并在就绪后支撑事件循环。具体事件类型与 API 见第 4 章。
