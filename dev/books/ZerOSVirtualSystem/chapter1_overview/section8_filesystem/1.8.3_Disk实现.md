# 1.8.3 Disk 实现

## 本节导读

本节将介绍 ZerOS 中文件系统核心组件 Disk 的实现要点。Disk 与 NodeTree、FileFramework 等配合，提供分区、目录树与文件读写等能力；详细实现见第 3 章，本节仅建立概述级认识。

---

## Disk 在启动中的角色

### 功能概览

Disk 在依赖图中通常与 NodeTree、FileFramework 一起构成文件系统层，并可能依赖类型池（如 fileType）。加载后通过**文件系统初始化（init.js）**挂接到实际存储后端（如 PHP/本地接口），并向 **POOL** 或全局暴露分区与文件操作接口。其提供的核心能力包括：

- **分区与存储抽象**：将逻辑分区（如 C:、D:）映射到底层存储或后端 API，为上层提供统一的“磁盘”视图。
- **与 NodeTree、FileFramework 的配合**：NodeTree 维护目录树结构，FileFramework 提供文件读写与路径解析；Disk 负责底层读写与分区管理，三者共同构成 1.8 节所述的文件系统。
- **为 LStorage、应用数据提供基础**：本地存储（LStorage）与许多系统扩展依赖文件系统初始化完成后的 Disk/NodeTree，因此 Disk 就绪是“持久化与用户数据”可用的前提。

### 与启动流程的关系

在启动流程图中，Disk 与 NodeTree、FileFramework 属于内核层，在类型池之后、内存与进程之前或并行；文件系统初始化（init）在其后执行，再被 LStorage、主题、用户控制等依赖。理解这一点有助于在排查“启动到某一步失败”时判断是否与文件系统或后端服务有关。

---

## 本节小结

本节概述了 Disk 的职责：在引导流程中提供分区与存储抽象，与 NodeTree、FileFramework 共同构成文件系统，并为 LStorage 及系统扩展提供基础。具体 API 与后端对接见第 3 章。
