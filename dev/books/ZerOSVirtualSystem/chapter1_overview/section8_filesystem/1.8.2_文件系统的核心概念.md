# 1.8.2 文件系统的核心概念

## 本节导读

本节将介绍文件系统的核心概念，即**文件**与**目录**这两个基本抽象。ZerOS 通过 Disk、NodeTree、FileFramework 等组件提供类似传统文件系统的能力，本节建立的概念是理解其设计与 API 的基础。

---

## 文件与目录

### 文件

**文件（File）** 是文件系统提供的**存储数据的基本单元**。从用户或程序的角度看，文件通常具有以下特征：

- **命名**：通过文件名（及所在路径）唯一标识，便于读写时指定对象。
- **内容**：可视为字节序列或文本流，支持顺序或随机读写、追加、截断等操作。具体是“字节流”还是“记录流”由文件系统或上层协议决定。
- **元数据**：除内容外，文件还带有属性信息，如大小、创建时间、修改时间、权限、类型等。这些元数据用于管理、检索和权限控制。

在 ZerOS 中，文件可能对应后端存储上的一段数据或一个虚拟节点，通过 Disk 和文件框架暴露为统一的“文件”抽象，使应用无需关心底层是本地存储、网络还是浏览器限制下的持久化方案。

### 目录

**目录（Directory）** 用于**组织文件**，形成层次化的命名空间。目录本身也可以视为一类特殊对象：

- **层次结构**：目录可包含文件或子目录，从而形成树状结构。路径（如 `/home/user/docs`）表示从根目录到某文件或目录的遍历路径。
- **命名与查找**：在目录下，子项（文件或子目录）的名字在同一层级内通常唯一，通过“目录 + 名字”可以定位到具体项。目录提供“列出子项”“按名查找”“创建/删除子项”等操作。
- **与文件的区别**：目录一般不存储用户数据流，而是存储“目录项”（名字到 inode 或节点的映射）。读写接口上，目录多提供枚举、查找等元数据操作，而文件提供读写内容的能力。

ZerOS 的 NodeTree 等结构即负责维护这类层次关系，与 Disk 的存储抽象配合，共同呈现为“文件系统”的完整视图。

---

## 本节小结

本节介绍了文件系统的核心概念：**文件**是存储数据的基本单元，具有名称、内容和元数据；**目录**用于组织文件与子目录，形成树状路径结构。掌握文件与目录的区分与关系，有助于理解 ZerOS 中 Disk 与文件框架的职责划分。
