# 1.7.3 MemoryManager 实现

## 本节导读

本节将介绍 ZerOS 中内存管理（MemoryManager）的实现要点。MemoryManager 与 Heap、Shed 等配合，为内核与应用提供内存分配与回收；详细实现见第 3 章，本节仅建立概述级认识。

---

## MemoryManager 在启动中的角色

### 功能概览

MemoryManager 在依赖图中通常依赖类型/枚举（如 addressType、logLevel）以及 Heap、Shed 等底层结构，加载后向 **POOL** 注册，供进程管理、文件系统等模块使用。其提供的核心能力包括：

- **内存分配与回收**：提供按大小或类型的分配接口，并在适当时机回收（如进程退出时回收其占用的堆内存），避免泄漏。
- **堆与栈的抽象**：通过 Heap 管理动态分配块，通过 Shed 或类似结构管理栈式生命周期，与 1.7.2 中的概念对应。
- **与进程的配合**：ProcessManager 创建进程时可能通过 MemoryManager 分配进程私有内存；进程终止时由 MemoryManager 或 ProcessManager 协同回收。

### 与启动流程的关系

在启动流程图中，MemoryManager 位于内核层，在文件系统与类型池之后、ProcessManager 之前。进程管理依赖内存管理来为每个进程提供地址空间或堆栈，因此其就绪是 ProcessManager 及后续系统层可用的前提。

---

## 本节小结

本节概述了 MemoryManager 的职责：在引导流程中提供内存分配与回收、堆/栈抽象，并向 POOL 注册供进程管理等模块使用。具体 Heap/Shed 实现见第 3 章。
