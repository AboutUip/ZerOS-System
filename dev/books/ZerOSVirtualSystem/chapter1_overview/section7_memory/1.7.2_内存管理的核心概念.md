# 1.7.2 内存管理的核心概念

## 本节导读

本节将介绍内存管理的核心概念，重点区分**堆内存**与**栈内存**在用途与管理方式上的不同。ZerOS 在浏览器环境中通过 MemoryManager、Heap、Shed 等组件提供类似抽象，本节建立的概念有助于理解后续实现。

---

## 堆内存与栈内存

### 堆内存

**堆（Heap）** 用于存储**动态分配**的数据：生命周期不随单次函数调用结束而结束，且大小往往在运行时才确定（如根据用户输入或配置分配）。典型用法包括：

- 动态创建的对象、数组、缓冲区等，其存活时间可能跨越多次函数调用，或由多个模块共享。
- 由程序显式申请（如 `malloc`/`new` 或 ZerOS 提供的分配接口）并在适当时机释放。若只申请不释放，会导致内存泄漏；若重复释放或使用已释放内存，会导致未定义行为或崩溃。

堆的管理由内存管理器负责：维护空闲块、分配与回收、可选地做碎片整理或池化。ZerOS 的 Heap 即承担此类职责，为上层提供“按需分配、用毕归还”的能力。

### 栈内存

**栈（Stack）** 用于存储**与函数调用和局部变量相关**的数据：每次函数调用时压入栈帧（如返回地址、局部变量、部分临时结果），函数返回时弹出。其特点是：

- 生命周期与函数调用绑定，无需显式释放，离开作用域即自动“回收”（栈指针回退）。
- 分配与回收顺序严格（后进先出），实现简单、开销小，但不适合存储生命周期不确定或需要跨调用共享的大块数据。

在 ZerOS 的语境中，“栈”可能指 JavaScript 执行栈，也可能指内核或应用层维护的“每进程栈”抽象（如用于保存调用链或局部上下文）。与堆的显式分配/释放相比，栈更偏“自动管理”，二者配合构成程序对内存的主要使用方式。

---

## 本节小结

本节介绍了内存管理的核心概念：**堆内存**用于动态分配、生命周期由程序控制的数据，由内存管理器负责分配与回收；**栈内存**用于函数调用与局部变量，生命周期与调用栈绑定、自动管理。理解二者区别，有助于后续学习 MemoryManager、Heap、Shed 在 ZerOS 中的分工。
