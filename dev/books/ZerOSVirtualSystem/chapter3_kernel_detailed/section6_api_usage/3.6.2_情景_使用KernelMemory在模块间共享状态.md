# 3.6.2 情景：使用 KernelMemory 在模块间共享状态

## 情景描述

内核中的多个模块需要**共享一些持久化状态**，例如进程表、磁盘分区信息、应用的持久化元数据等。ZerOS 使用 `KernelMemory` 作为统一的“内核级存储”，各模块通过统一接口读写其中的不同“地址空间”。

本节给出一个简化情景：`ProcessManager` 使用 `KernelMemory` 持久化进程表，另一个模块（例如诊断模块）读取同一份数据进行分析。

---

## 前置条件

- `KernelMemory` 模块已在内核初始化时就绪，并注册到 `POOL` 中（或以其他方式在模块间共享）。
- 约定好一个用于存储进程表的键，例如 `'kernel.processTable'`。

---

## 情景 A：ProcessManager 保存进程表

```js
// ProcessManager 内部
function _saveProcessTable() {
    const KernelMemory = POOL.get('KernelMemory');
    if (!KernelMemory) {
        throw new Error('KernelMemory 未就绪');
    }

    const table = this._getProcessTable(); // 内存中的进程表
    KernelMemory.saveData('kernel.processTable', table);
}
```

要点：

- `saveData(key, value)` 负责把对象序列化并写入底层存储（可能映射到磁盘或 Exploit 内存）。
- 键名约定统一，便于其他模块读取。

---

## 情景 B：诊断模块读取进程表

```js
// 位于内核诊断模块内部
function dumpProcessTable() {
    const KernelMemory = POOL.get('KernelMemory');
    if (!KernelMemory) {
        throw new Error('KernelMemory 未就绪');
    }

    const table = KernelMemory.loadData('kernel.processTable') || {};
    Object.keys(table).forEach(pid => {
        const info = table[pid];
        console.log('PID:', pid, 'status:', info.status, 'name:', info.name);
    });
}
```

这里通过 `loadData(key)` 读取与 `saveData` 相同键下的内容，实现跨模块共享。

---

## 行为小结

| 步骤 | 行为 |
|------|------|
| 写入 | 生产者模块通过 `KernelMemory.saveData('kernel.xxx', value)` 持久化状态 |
| 读取 | 消费者模块通过 `KernelMemory.loadData('kernel.xxx')` 读取相同键对应的数据 |

通过这个情景，读者可以把 `KernelMemory` 理解为“内核内部共享的 KV 存储”，各模块围绕统一的键名协作，而不必直接共享 JS 对象引用。
