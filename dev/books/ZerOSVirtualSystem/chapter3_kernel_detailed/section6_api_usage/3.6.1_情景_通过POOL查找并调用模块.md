# 3.6.1 情景：通过 POOL 查找并调用模块

## 情景描述

在内核层中，一个模块往往需要**调用另一个模块的接口**。例如，`ProcessManager` 需要拿到 `MemoryManager`，或 `Disk` 需要访问 `KernelMemory`。ZerOS 通过全局的 `POOL` 作为“模块发现与注册表”，在 Kernel 内部完成这种“查找并调用”。

本节给出一个最小情景：在某个内核模块中，通过 `POOL` 查找 `MemoryManager`，并调用它暴露的接口。

---

## 前置条件

- 目标模块（如 `MemoryManager`）在初始化时已将自己注册到 `POOL` 中，例如：

```js
// 内核模块初始化处
POOL.register('MemoryManager', MemoryManager);
```

- 当前代码运行在 `kernel/` 内部（不是应用层），可以直接访问 `POOL`。

---

## 核心代码

```js
// 位于某内核模块内部（例如 ProcessManager）
function _getProcessHeap(pid) {
    // 1. 通过 POOL 获取 MemoryManager
    const MemoryManager = POOL.get('MemoryManager');
    if (!MemoryManager) {
        throw new Error('MemoryManager 未注册到 POOL 中');
    }

    // 2. 调用 MemoryManager 提供的接口
    return MemoryManager.getHeapByPid(pid);
}
```

要点：

- `POOL.get(name)` 返回之前通过 `POOL.register(name, instance)` 注册的模块实例；若未注册，返回 `undefined`。
- 内核模块之间的依赖通过字符串 `name` 管理，避免直接 `import` 循环。

---

## 行为小结

| 步骤 | 行为 |
|------|------|
| 模块 A 初始化时 | 调用 `POOL.register('MemoryManager', MemoryManager)` 把自己挂到注册表 |
| 模块 B 需要使用时 | 调用 `POOL.get('MemoryManager')` 拿到实例，并使用其公开方法 |

通过这个情景，读者可以把 POOL 理解为“内核内部的服务发现中心”，内核模块之间不直接互相 `new`，而是通过 POOL 进行解耦。
