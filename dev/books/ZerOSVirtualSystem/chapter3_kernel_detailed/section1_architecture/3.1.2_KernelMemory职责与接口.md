# 3.1.2 KernelMemory 的职责与接口

## 本节导读

KernelMemory 是内核层中负责“可序列化状态”存储的模块，通常由 `kernel/memory/kernelMemory.js` 提供，对外暴露 **loadData(key)** 与 **saveData(key, value)**。本节说明其职责、典型 key 的含义（PROCESS_TABLE、APPLICATION_SOP、DISK_SEPARATE_MAP、PROGRAM_NAMES 等）、以及与 Exploit 内存或后端持久化的关系；并简要说明序列化与反序列化时对 Map/Set 等结构的处理方式（与 ProcessManager、MemoryManager、Disk 的保存/加载逻辑一致）。

---

## 一、职责与定位

KernelMemory 的职责可概括为：

1. **键值持久化**：为内核各子模块提供按 key 存储与读取数据的能力，value 通常为可 JSON 序列化的结构（或经各模块自行序列化后的数组/对象）。
2. **与 Exploit 内存的对接**：在 ZerOS 中，内核“内存”可能对接浏览器端的 Exploit 存储（如 IndexedDB、LocalStorage 的封装）或后端接口；loadData/saveData 屏蔽具体存储介质，使 ProcessManager、MemoryManager、Disk 等只依赖“键值读写”语义。
3. **生命周期**：与内核同生共死，在模块加载后初始化，在页面关闭或刷新前持久化写入，下次启动时通过 loadData 恢复。

---

## 二、典型 key 与使用方

| key | 使用模块 | 含义 |
|-----|----------|------|
| PROCESS_TABLE | ProcessManager | 进程表序列化（Map<pid, ProcessInfo> 转为数组等可序列化结构） |
| APPLICATION_SOP | MemoryManager | 各 pid 的内存分区元数据（nextHeapId、nextShedId 等；Heap/Shed 对象本身不序列化） |
| PROGRAM_NAMES | MemoryManager | pid → 程序名的映射，用于展示与排查 |
| DISK_SEPARATE_MAP | Disk | 分区名称列表（NodeTreeCollection 对象在 POOL 中，此处只存名称以便重启后从 POOL 按名取回或重建） |

各模块在需要持久化时调用 `KernelMemory.saveData(key, serializedValue)`，在初始化或查询时调用 `data = KernelMemory.loadData(key)`，再自行反序列化为 Map 等结构（如 ProcessManager._getProcessTable、MemoryManager._getApplicationSOP、Disk._getDiskSeparateMap）。

---

## 三、序列化与反序列化约定

- **Map**：可转为 `Array.from(map.entries())` 再 JSON 序列化；反序列化时 `new Map(array)`。
- **Set**：可转为 `Array.from(set)`；反序列化时 `new Set(array)`。
- **不可序列化引用**：如 DOM 元素、MutationObserver、Heap/Shed 运行时对象等，在保存时省略或置 null，加载时重建空集合或默认值，避免报错或冗余存储。

ProcessManager 的 _saveProcessTable 中会对 memoryRefs、domElements、requestedModules 等做 Map/Set 与数组的转换；MemoryManager 的 _saveApplicationSOP 只保存 nextHeapId、nextShedId 等元数据，不保存 Heap/Shed 对象本身；Disk 的 _saveDiskSeparateMap 只保存分区名数组。这些约定与 KernelMemory 的“键值存储”一起，构成内核层持久化的统一方式。

---

## 四、行为流程与接手维护要点

**典型读写流程**：各模块在初始化或需要恢复状态时调用 `data = KernelMemory.loadData(key)`，再按约定将 data 反序列化为 Map 等（如 ProcessManager._getProcessTable）；在状态变更后调用 `KernelMemory.saveData(key, serializedValue)`，serializedValue 由各模块自行序列化（如 Array.from(table.entries())）。  

**不可序列化对象**：若某模块需要存储不可 JSON 序列化的对象（如 DOM、函数），应只将可序列化的“元数据”或“键”存入 KernelMemory，将实际对象放在内存或 POOL 中，通过键或名称在加载后关联；与 Disk 的“只存分区名、对象在 POOL”策略一致。  

**APPLICATION_SOP 不存 Heap/Shed**：Heap/Shed 含运行时引用且可能含函数，无法安全序列化；只存 nextHeapId、nextShedId 即可在重启后恢复 ID 计数，避免冲突；堆/栈内容若需持久化由应用层或上层用其他 key 或后端完成。

## 五、本节小结

KernelMemory 通过 loadData/saveData 提供键值持久化，是进程表、内存分区元数据、磁盘分区列表等的存储中心；各模块自行负责序列化/反序列化及 Map/Set 与不可序列化引用的处理；典型 key 包括 PROCESS_TABLE、APPLICATION_SOP、DISK_SEPARATE_MAP、PROGRAM_NAMES 等。
