# 3.4.1 Disk 与分区映射

## 本节导读（阅读目标）

本节使读者能够：**① 完全理解 Disk 的职责与 diskSeparateMap 在内存中的结构（Map<分区名, NodeTreeCollection>）及与 KernelMemory/POOL 的分工；② 明确 _getDiskSeparateMap 与 _saveDiskSeparateMap 的每一行逻辑：KernelMemory 不可用时的降级、只存分区名数组的原因、从 POOL 按名取 NodeTreeCollection 的时机；③ 掌握 diskSeparateMap getter 的缓存与 _getDiskSeparateSize 等其它持久化 key；④ 接手维护时能正确保证“分区先注册到 POOL 再被 Disk 读取”、排查“分区消失”或扩展分区元数据。** 下文给出**带行号与中文注释的完整源码**、**行为流程**与**接手维护要点**。源码文件：`kernel/fileSystem/disk.js`。

---

## 一、Disk 的职责与数据结构（源码注释约 15–21 行）

- **diskSeparateMap**：Map<分区名, NodeTreeCollection>，描述分区名到分区对象的映射。NodeTreeCollection 是运行时对象（目录树等），存在 **POOL** 中；KernelMemory 只存分区名列表。
- **diskSeparateSize / diskFreeMap / diskUsedMap**：分区大小、空闲、已用等元数据，各自对应 KernelMemory 的 DISK_SEPARATE_SIZE 等 key（见 _getDiskSeparateSize 等）。
- **canUsed**：表示磁盘是否已初始化。

---

## 二、_getDiskSeparateMap — 完整源码与注释（约 29–61 行）

```javascript
    static _getDiskSeparateMap() {
        if (typeof KernelMemory === 'undefined') {
            if (!Disk._fallbackDiskSeparateMap) {
                Disk._fallbackDiskSeparateMap = new Map();
            }
            return Disk._fallbackDiskSeparateMap;
        }

        const data = KernelMemory.loadData('DISK_SEPARATE_MAP');
        if (data) {
            const map = new Map();
            if (Array.isArray(data)) {
                for (const separateName of data) {
                    if (typeof POOL !== 'undefined' && typeof POOL.__GET__ === 'function') {
                        try {
                            const coll = POOL.__GET__("KERNEL_GLOBAL_POOL", separateName);
                            if (coll) {
                                map.set(separateName, coll);
                            }
                        } catch (e) {
                            KernelLogger.debug("Disk", `无法从POOL获取分区 ${separateName}`);
                        }
                    }
                }
            }
            return map;
        }

        const newMap = new Map();
        Disk._saveDiskSeparateMap(newMap);
        return newMap;
    }
```

**行为流程**：  
1. KernelMemory 未定义 → 返回 _fallbackDiskSeparateMap（单例空 Map）。  
2. data = KernelMemory.loadData('DISK_SEPARATE_MAP')；DISK_SEPARATE_MAP 存的是**分区名数组**（如 ["C:", "D:"]）。  
3. 有数据则遍历分区名，对每个名用 `POOL.__GET__("KERNEL_GLOBAL_POOL", separateName)` 取 NodeTreeCollection；若存在则 map.set(separateName, coll)；取不到则打 debug 日志并跳过，该分区不会出现在返回的 map 中。  
4. 无数据则新建 Map 并 _saveDiskSeparateMap(newMap)，返回 newMap。

**设计原因**：NodeTreeCollection 不可序列化或过于复杂，故只持久化“有哪些分区”；重启后文件系统初始化逻辑先将各分区对象注册到 POOL（名称与 DISK_SEPARATE_MAP 中一致），Disk 再通过 _getDiskSeparateMap 按名取回，形成“名称持久化 + 对象在 POOL”的分离存储。

---

## 三、_saveDiskSeparateMap — 完整源码与注释（约 67–76 行）

```javascript
    static _saveDiskSeparateMap(map) {
        if (typeof KernelMemory === 'undefined') return;
        const names = Array.from(map.keys());
        KernelMemory.saveData('DISK_SEPARATE_MAP', names);
    }
```

只保存分区名列表，不保存 NodeTreeCollection；NodeTreeCollection 的持久化（若有）由其他模块或后端负责，Disk 只负责“有哪些分区”的元数据。

---

## 四、diskSeparateMap getter 与缓存（约 82–90 行）

```javascript
    static get diskSeparateMap() {
        if (Disk._diskSeparateMapCache) {
            return Disk._diskSeparateMapCache;
        }
        const map = Disk._getDiskSeparateMap();
        Disk._diskSeparateMapCache = map;
        return map;
    }
```

首次访问时 _getDiskSeparateMap() 并写入缓存；后续直接返回缓存。若别处修改了 DISK_SEPARATE_MAP 或 POOL 中的分区注册，缓存不会自动失效，需在需要刷新的地方清除 _diskSeparateMapCache 或通过 Disk 提供的接口更新。

---

## 五、行为流程小结（分区从持久化到内存）

1. 文件系统初始化时，各分区（如 "C:", "D:"）的 NodeTreeCollection 先注册到 POOL：`POOL.__ADD__("KERNEL_GLOBAL_POOL", "C:", nodeTreeCollectionC)` 等。  
2. 某处访问 Disk.diskSeparateMap 或调用 _getDiskSeparateMap()。  
3. loadData('DISK_SEPARATE_MAP') 得到 ["C:", "D:", ...]；对每个名从 POOL 取对象，组成 Map<分区名, NodeTreeCollection> 返回。  
4. 新增或删除分区时，更新内存中的 map 并调用 _saveDiskSeparateMap(map)，只写名称数组到 KernelMemory。

---

## 六、接手维护要点

- **“分区消失”**：若某分区名在 DISK_SEPARATE_MAP 中但尚未在 POOL 中注册，_getDiskSeparateMap 会跳过该名（coll 为 undefined），导致该分区不在返回的 map 中。**初始化顺序**应保证：先由文件系统/init 或相关逻辑将各分区 NodeTreeCollection 注册到 POOL，再让 Disk 读取 DISK_SEPARATE_MAP 并按名取回。  
- **扩展分区元数据**：分区大小、空闲、已用等已在 _getDiskSeparateSize、_getDiskFreeMap、_getDiskUsedMap 等中通过 KernelMemory 的其它 key 持久化；若新增元数据，可新增 key 或扩展现有序列化结构，与 _saveDiskSeparateMap 只存名称的策略一致。  
- **分区树结构持久化**：若希望目录树也持久化，应在 NodeTree/FileFramework 或后端层以单独 key 或接口存储，Disk 层只负责“分区名列表”；加载时先恢复分区名列表，再按名从 POOL 取 NodeTreeCollection（或由其它模块从持久化恢复树结构后注册到 POOL）。
