# 3.5.2 loadData 与 saveData 的地址映射与分配算法

## 本节导读（阅读目标）

本节让读者**完完全全参透** KernelMemory 的 **saveData(key, data)** 与 **loadData(key)** 的**算法细节**：key 对应的数据如何以 JSON 字符串形式按**字符**写入 Heap、key 的**起始地址与长度**如何存入 Shed 的 resourceLinkArea（key_ADDR、key_SIZE）、以及 **_allocatedRanges** 与**两轮线性分配 + 碎片清理**的策略。学完后能说出一次 saveData 的完整步骤与一次 loadData 的完整步骤，并能分析“保存失败”或“加载为 null”的常见原因。源码：`kernel/memory/kernelMemory.js` 约 202–490 行。

---

## 一、存储模型概览

- **Heap**：一段连续“格子”，每个格子存一个**字符**（或单字符字符串）。多个 key 的数据在 Heap 上占用不同**地址区间**，互不重叠。
- **Shed**：通过 **resourceLinkArea**（或等价接口）存储“键名 → 元数据”。对每个 key，存两条：`key_ADDR` = 起始地址（字符串），`key_SIZE` = 数据长度（字符串）。loadData 时先读 key_ADDR/key_SIZE，再按 addr+size 从 Heap 逐字符读出并拼成 JSON 字符串，最后 JSON.parse。
- **_allocatedRanges**：Map<startAddr, { size, key }>，记录已分配的区间，用于 saveData 时**冲突检测**与**释放旧区间**（同 key 覆盖时先清旧再写新）。

---

## 二、saveData(key, data) 的算法步骤（源码 202–406 行）

1. **防循环**：若 key === 'APPLICATION_SOP' 且 MemoryManager._loadingApplicationSOP 为 true，直接 return false。
2. **_ensureMemory()**：取得 heap、shed；若失败 return false。
3. **序列化**：jsonStr = JSON.stringify(data)，dataSize = jsonStr.length。
4. **容量检查**：若 dataSize > heap.heapSize，return false。
5. **查旧数据**：从 shed 读 key_ADDR、key_SIZE；若存在则得到 oldAddr、oldSize；将旧区间在 Heap 上填 null，_allocatedRanges.delete(oldAddr)；若 dataSize <= oldSize 可**重用** startAddr = oldAddr，否则进入分配。
6. **分配**（无旧或新更大）：
   - **第一轮**：从 _nextAddress 开始线性扫描，检查 [addr, addr+dataSize) 是否与 _allocatedRanges 中任一区间重叠；无冲突则 startAddr = addr，_nextAddress = addr + dataSize，break。
   - **第二轮**：若第一轮未找到，从 0 开始扫描（处理碎片），同上冲突检测，找到则 break。
   - **第三轮**：若仍未找到，尝试**清理无效范围**（shed 中某 range.key 对应的 _ADDR 已不是该 allocatedAddr），删除该 range 并清空 Heap 上该区间，再从头扫描一次。
7. **写 Heap**：对 startAddr 起 dataSize 个格子，逐字符写入 jsonStr[i]（单字符或 ''）；若 Heap.writeData 失败 return false。
8. **记元数据**：_allocatedRanges.set(startAddr, { size: dataSize, key })；shed.writeResourceLink(key_ADDR, String(startAddr))，shed.writeResourceLink(key_SIZE, String(dataSize))。
9. return true。

---

## 三、loadData(key) 的算法步骤（源码 413–490 行）

1. **防循环**：若 key === 'APPLICATION_SOP' 且 MemoryManager._loadingApplicationSOP，return null。
2. **_ensureMemory()**：取得 heap、shed；若失败 return null。
3. **读元数据**：addrStr = shed.readResourceLink(key_ADDR)，sizeStr = shed.readResourceLink(key_SIZE)；若无则 return null。
4. **解析**：addr = parseInt(addrStr)，size = parseInt(sizeStr)；非法则 return null。
5. **读 Heap**：从 addr 起 size 个格子，逐格 memory.heap.readData(addr+i)，拼成 jsonStr；若遇连续超过 maxNullCount 个 null 则提前结束（防止越界或脏数据）。
6. **反序列化**：try { return JSON.parse(jsonStr); } catch { return null; }。

---

## 四、两轮分配与碎片

- **第一轮从 _nextAddress 开始**：优先使用“尾部”连续空间，减少碎片。
- **第二轮从 0 开始**：释放或覆盖旧数据后，前面可能产生空洞，从头扫描可复用空洞。
- **清理无效范围**：若某次 saveData 曾失败或 key 被删，_allocatedRanges 中可能仍保留该区间，但 shed 中已无该 key 的 _ADDR 或已指向别处；通过遍历 _allocatedRanges 与 shed 对比，可释放“已无效”的区间，再分配。

---

## 五、本节小结与维护要点

- saveData：序列化 → 释放/重用旧区间或两轮分配+清理 → 逐字符写 Heap → 写 key_ADDR/key_SIZE 到 Shed → 记 _allocatedRanges。
- loadData：读 key_ADDR/key_SIZE → 从 Heap 逐字符读 → JSON.parse。
- “保存失败”常见原因：_ensureMemory 失败、dataSize > heapSize、两轮+清理后仍无空闲区间；“加载为 null”：key 从未保存、或 APPLICATION_SOP 防循环导致故意返回 null、或 JSON 损坏。
