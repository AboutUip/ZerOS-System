# 3.2.3 进程启动的完整调用链

## 本节导读（阅读目标）

本节让读者**完完全全参透**从用户或系统“启动一个程序”到**进程表写入、内存分配、窗口注册**的**完整调用链**：谁调用了 ProcessManager 的哪个 API、何时分配 PID、何时创建 ProcessInfo、何时调用 MemoryManager.allocateMemory、何时调用 GUIManager.registerWindow，以及各步在源码中的大致位置。学完后能沿调用链排查“进程启动失败”或“窗口未出现”的断点。源码：`kernel/process/processManager.js`、`kernel/memory/memoryManager.js`、`system/ui/guiManager.js`。

---

## 一、入口：startProgram / run 等

用户通过桌面快捷方式、任务栏、或 run 程序启动时，最终会调用 **ProcessManager** 的启动接口（如 **startProgram(programName, initArgs)** 或内部封装）。该接口是进程启动的**唯一正规入口**，负责协调 PID 分配、进程表、内存与（可选）GUI。

---

## 二、调用链（按时间顺序）

1. **ProcessManager.startProgram(programName, initArgs)**（或等价 API）
   - **PID 分配**：调用 **_allocatePid()**，得到唯一 pid；若失败则 throw。
   - **进程表**：调用 **_getProcessTable()** 取得 Map（可能从 KernelMemory 反序列化）；构造 **ProcessInfo**（pid、programName、scriptPath、status='loading'、memoryRefs=new Map()、domElements=new Set()、requestedModules=new Set()、isBackground 等）；**table.set(pid, info)**；**_saveProcessTable(table)** 持久化。
   - **内存**：调用 **MemoryManager.allocateMemory(pid, heapSize, shedSize, ...)**，为该 pid 在 APPLICATION_SOP 中建立或获取分区，分配 Heap/Shed；若 _canAllocateMemory() 为 false 则 throw。
   - **程序名映射**：**MemoryManager.registerProgramName(pid, programName)**，写入 PROGRAM_NAMES 并持久化。
   - **加载脚本**：根据 programName 或 scriptPath 加载应用脚本（如通过 Disk/NodeTree 或动态模块）；脚本执行后可能创建窗口并调用 **GUIManager.registerWindow(pid, windowElement, options)**。
   - **状态更新**：脚本或框架初始化完成后，**updateProcessInfo(pid, { status: 'running' })** 并 **_saveProcessTable**。

2. **MemoryManager.allocateMemory(pid, ...)**
   - 检查 _canAllocateMemory()；取 APPLICATION_SOP，若无 pid 则 sop.set(pid, { heaps, sheds, nextHeapId: 1, nextShedId: 1 }) 并 _saveApplicationSOP；分配 nextHeapId/nextShedId，new Heap/new Shed，写入 appSpace.heaps/sheds；_saveApplicationSOP。

3. **GUIManager.registerWindow(pid, windowElement, options)**（由应用脚本或内核封装调用）
   - 分配 windowId、z-index，_windows.set(windowId, info)，_pidToWindows.get(pid).add(windowId)，挂载 DOM 与控件。

---

## 三、关键断点与排查

- **“启动后无进程”**：检查 startProgram 是否被调用、_allocatePid 是否抛错、_saveProcessTable 是否执行、KernelMemory 是否可用。
- **“启动后无窗口”**：检查应用脚本是否调用了 GUIManager.registerWindow、是否在 ProcessManager 完成进程表与内存分配之后调用。
- **“内存分配失败”**：检查 _canAllocateMemory（bios.memoryAllocation）、APPLICATION_SOP 是否已就绪、_ensureMemory 是否成功（若应用脚本间接依赖 KernelMemory）。

---

## 四、本节小结

进程启动的完整链路：startProgram → _allocatePid → _getProcessTable → 构造 ProcessInfo → _saveProcessTable → allocateMemory → registerProgramName → 加载脚本 → （脚本内）registerWindow → updateProcessInfo(status: 'running') → _saveProcessTable。理解此链即可在任意一步设断点或打日志排查问题。
